论文阅读：Spatial Foundry

发表于2026-11-20|更新于2026-11-22
|总字数:3.6k|阅读时长:12分钟|浏览量:—

引：Spatial Foundry 做了一批可以在电脑里打开、修改和拍摄的住宅场景。它的重点不只是给出房子的图片，还把图片对应的三维几何、相机位置和物体信息放在一起。这样我们既可以问“从另一个位置看这间屋子是什么样”，也可以把桌子挪走，再观察同一条路线上的画面会怎么变化。

图来自原论文 Figure 2：同一套住宅对应的平面图、点云、网格、图像、深度和相机轨迹。

背景

假设我们拿着相机走进一间客厅，拍到沙发、桌子和窗户。只看一张照片，我们能认出这些东西，但很难准确知道桌子离相机几米、沙发背后是什么，或者走到门口回头时会看到什么。训练模型回答这类问题，需要把照片与它背后的三维场景联系起来：照片从哪里拍的，物体在哪里，有没有被移动过。

已有数据集各有侧重。比如 RealEstate10K 提供视频及估计出的相机轨迹，Hypersim 提供合成图像和几何标注，ProcTHOR 提供可交互的程序化环境 (Zhou et al., 2018; Roberts et al., 2021; Deitke et al., 2022)。Spatial Foundry 想把这些信息组织到同一批可编辑场景中，以便按需要生成配对数据。

最容易理解的例子是 先固定房间，只改变相机位置：从门口和窗边分别拍摄，就得到同一个房间的不同视角。反过来，固定相机路线，把桌子挪开后再拍一遍，两段视频的差别就来自场景编辑。这样的配对可以用来研究模型是否理解相机运动和物体变化。

数据集

Spatial Foundry 包含 5,280 套布置好家具的住宅场景配置。这里一套配置指住宅布局加上一种家具和物品摆放；同一平面布局可以搭配不同的家具方案，因此这个数字不等于独立户型的数量。场景以美式住宅为主，包含不同房间组合和多层布局。

每套场景都保留了可编辑的三维资产。作者从中生成平面图、普通视角和 360° 全景 RGB、深度图、网格、点云、物体的三维包围盒，以及与相机轨迹配对的视频。它们之间的关系可以用一张客厅照片来理解：

  • RGB 是相机看到的颜色；深度图则记录每个有效像素对应表面离相机的距离，单位为米。
  • 相机参数和位姿 记录相机怎样成像、放在哪里、朝向哪里。结合深度，可以把照片上的像素还原到三维空间。
  • 网格和点云 分别用相连的三角形表面和一组空间点表示几何；物体包围盒则用一个长方体描述物体的位置和范围。
  • 实例 ID 用来区分场景中的具体物体。例如，两张照片里出现同一张桌子，可以通过 ID 把它们关联起来；视频帧还记录了时间和对应的相机位姿。

这些数据使用同一个场景坐标系，长度以米为单位。因此照片中的桌子、三维模型中的桌子和标注里的桌子可以对应起来。作者将一次观测概括为

os,t=(Is,t,Ds,t,Πs,t,Ts,twc,τs,t),o_{s,t}=\big(I_{s,t},D_{s,t},\Pi_{s,t},T^{\mathrm{wc}}_{s,t},\tau_{s,t}\big), os,t​=(Is,t​,Ds,t​,Πs,t​,Ts,twc​,τs,t​),

其中 III、DDD 分别是图像和深度，Π\PiΠ 描述相机投影及标定，TwcT^{\mathrm{wc}}Twc 将相机坐标转换到世界坐标，τ\tauτ 是时间。这个表示记录了一帧画面及其配套信息。物体引用另行连接到场景的实例表。

项目页还提供可交互的彩色点云预览。点的颜色来自材质、纹理或渲染图像，具体来源会记录下来；它主要帮助我们查看场景，不应直接当成物体材质的固有颜色。

场景构建

作者先生成住宅平面，再把平面搭成有家具的三维场景，最后从场景中导出几何、图像和视频。下面沿着这条过程看，每一步究竟产生了什么。

图来自原论文 Figure 3：从住宅规则生成布局，再搭建场景并生成观测。

布局生成

首先要决定房子有几层、有哪些房间、房间怎么连通。作者把住宅设计中关于门洞、通道和楼梯的要求，以及墙厚等参数整理成规则，再提供厨房和卫生间等空间的常见排布模板，让 GPT-6 生成平面布局。

图来自原论文 Figure 4：厨房和卫生间的几种排布模板。

这里生成的是一份结构化定义：每个房间的轮廓、墙、门洞、楼梯以及房间间的邻接关系。比如平面里写明厨房在客厅旁边、两者之间有门洞，后续程序才能据此搭墙和留出入口。作者将这一过程写成

P∼qGPT-6(P∣b,R,m),P=({Ωr},W,D,S,A).P\sim q_{\mathrm{GPT\text{-}6}}(P\mid b,\mathcal{R},m),\qquad P=\big(\{\Omega_r\},\mathcal{W},\mathcal{D},\mathcal{S},\mathcal{A}\big). P∼qGPT-6​(P∣b,R,m),P=({Ωr​},W,D,S,A).

bbb 是所需房间和楼层，R\mathcal{R}R 是规则，mmm 是排布模板；输出 PPP 中依次包含房间轮廓、墙体、开口、楼梯和邻接关系。生成后还要人工检查房间能否进入、通道是否畅通、楼梯能否连接各层；不合适的布局会修改或过滤。家具摆好后再检查一次，以免柜子堵住门或楼梯。

场景装配

通过检查的平面在 Blender 中变成三维房屋：地板、墙、门洞和楼梯按布局建立，再添加材质和家具。家具等资产来自 Infinigen 及 GPT-6 辅助的程序化生成 (Raistrick et al., 2024)。同一布局更换家具或材质，就可以得到另一套配置。

在这个场景中，一张桌子不只是画面上的一块颜色，它有自己的几何、位置、朝向和 ID。作者把整个场景记为 S=(G,O,M,L)S=(\mathcal{G},\mathcal{O},\mathcal{M},\mathcal{L})S=(G,O,M,L)，分别表示几何、物体实例表、材质和光照；物体 iii 的记录为 oi=(ιi,Gi,Ti,ℓi)o_i=(\iota_i,\mathcal{G}_i,T_i,\ell_i)oi​=(ιi​,Gi​,Ti​,ℓi​)，包括 ID、几何、变换和语义描述。比如移动桌子可以通过改变它的变换 TiT_iTi​ 实现，而 ID 用来关联移动前后的同一张桌子。

几何与物体标注

场景搭好后，作者提取世界坐标系中的网格，并把组成物体的网格部件归到相应实例。例如，桌面和桌腿可能是不同网格，但都属于同一张桌子。再从表面采样得到一份 参考点云：点的位置来自原始场景，点也保留所属物体的信息。

物体的轴对齐包围盒可以从它的顶点求出。对物体 iii 的世界坐标顶点 {vi,j}\{\mathbf{v}_{i,j}\}{vi,j​}，分别取各坐标的最小值和最大值：

bi−=min⁡jvi,j,bi+=max⁡jvi,j,di=bi+−bi−.\mathbf{b}^{-}_{i}=\min_j\mathbf{v}_{i,j},\qquad \mathbf{b}^{+}_{i}=\max_j\mathbf{v}_{i,j},\qquad \mathbf{d}_{i}=\mathbf{b}^{+}_{i}-\mathbf{b}^{-}_{i}. bi−​=jmin​vi,j​,bi+​=jmax​vi,j​,di​=bi+​−bi−​.

例如桌子所有顶点在东西方向上最小为 1 米、最大为 2 米，那么包围盒在这个方向上的长度就是 1 米。三个方向都这样计算，就得到盒子的范围和尺寸。它是沿世界坐标轴放置的盒子，桌子斜放时，盒子里也会包含一些空隙。

虚拟扫描

直接从完整模型采样得到的参考点云，和真实扫描仪看到的点云不同：扫描仪站在客厅时，看不到墙后面的物体，桌面也会挡住一部分桌腿。作者因此在房间中放置多个虚拟扫描位置，模拟从各处能看到哪些表面。

对每个扫描位置，作者按方向把周围空间划成小角度区域；同一方向上有多个表面点时，只保留最近的点，近似模拟遮挡。比如沿某个方向先遇到桌面、再遇到地板，那么该位置只保留桌面点。把多个位置看到的点合起来，就得到覆盖更多区域的扫描结果。这是基于采样点的遮挡近似，效果会受方向划分和点的密度影响。

每个保留下来的点，选择能看到它的最近扫描位置，并从该位置渲染的全景图中取颜色。接着作者给点的位置加入与距离有关的扰动，并混入少量较大的误差，模拟移动扫描中的部分噪声；另外还用一种射线投射方案模拟玻璃、镜子附近的部分透射、反射和无返回情况。原始参考几何单独保留，所以可以拿带扰动的扫描结果与原始场景对照。

RGB-D 与视频

除了扫描点云，同一个场景还可以用虚拟相机渲染 RGB 和深度图。知道相机内参、位姿和深度后，可以把像素对应的三维点放回世界坐标。对于使用相机轴向深度 zzz 的透视相机，论文给出

xw=R(zK−1u~)+t.\mathbf{x}_{w}=R\left(zK^{-1}\widetilde{\mathbf{u}}\right)+\mathbf{t}. xw​=R(zK−1u)+t.

这里 u~=(u,v,1)⊤\widetilde{\mathbf{u}}=(u,v,1)^\topu=(u,v,1)⊤ 是像素位置，KKK 是相机内参，RRR 和 t\mathbf{t}t 描述相机在世界中的朝向与位置。可以把它理解成两步：先用像素方向和深度求出点在相机前方的位置，再把这个位置转换到房间的坐标系里。若深度记录的是沿视线的距离，则需要使用归一化的射线；导出的记录会注明深度约定。

作者还设置连接房间和楼层的相机路线，逐帧保存图像、时间、相机参数和位姿。这样，一段从客厅走到卧室的视频不只是连续的画面：每一帧都能查到相机所在位置。路线经过楼梯时，相机高度随楼梯连续变化。

场景编辑

场景里的物体可以平移、旋转、加入、移除或改变外观。论文将编辑和重新渲染写成

St+1=F(St,at),It+1(k)=Rrender ⁣(St+1,Ct+1(k)).S_{t+1}=F(S_t,a_t),\qquad I_{t+1}^{(k)}=\mathcal{R}_{\mathrm{render}}\!\left(S_{t+1},C_{t+1}^{(k)}\right). St+1​=F(St​,at​),It+1(k)​=Rrender​(St+1​,Ct+1(k)​).

StS_tSt​ 是编辑前的场景，ata_tat​ 是编辑动作，St+1S_{t+1}St+1​ 是编辑后的场景；第 kkk 个相机从自己的位置观察新场景，得到图像 It+1(k)I_{t+1}^{(k)}It+1(k)​。举例来说，先记录桌子的位置，再把它移到窗边，然后让相机沿原路线重新拍摄。编辑记录和实例 ID 把两次观察联系起来，让我们知道画面变化对应的是哪次物体操作。

多个相机也可以观察同一串场景状态：一个在门口，一个在窗边，桌子移动后两者分别看到变化。这为研究多个观察者如何建立对同一环境的认识提供了数据。编辑对可以按需生成，或通过源资产获得。

应用

图来自原论文 Figure 5：数据集支持的应用示例。

作者讨论了以下用途，可以按任务取出不同的输入和监督：

  1. 平面图生成三维场景：输入平面图，预测房间结构和家具布置，用对应的三维场景作为参考。同一布局有多种家具配置，也说明平面图不唯一决定室内陈设。
  2. 三维重建：输入一张或多张图像，预测深度或几何，再用相机参数、深度和网格进行对照。
  3. 物体空间感知：从图像或点云中找出物体，预测它的位置和大小；实例 ID 还可以用来检查不同视角是否找到了同一个物体。
  4. 相机控制的视频生成：给定已有画面和目标相机路线，生成沿途画面。路线重新经过客厅时，可以检查模型是否还记得桌子和沙发的位置。
  5. 共享环境与场景编辑：利用多个相机观察同一状态，或利用编辑前后的配对数据，研究跨视角一致性和预测物体变化后的画面。

总结

Spatial Foundry 的核心是把一套住宅保留为可编辑的三维场景，再从它生成彼此对应的图片、几何、物体标注和视频。相机的位置、物体身份和坐标把这些数据连起来；固定场景改变相机，或固定相机路线改变场景，就能构造不同的比较。

这批合成场景以美式住宅为主，布局经过人工筛选，适合围绕住宅环境构造空间理解任务。
