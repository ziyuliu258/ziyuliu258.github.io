论文阅读：π0\pi_0π0​ - A Vision-Language-Action Flow Model for General Robot Control

发表于2026-11-05|更新于2026-11-06
|总字数:4.9k|阅读时长:16分钟|浏览量:—

引：π0\pi_0π0​ 将预训练视觉语言模型与一个较小的 action expert 接在一起：前者提供图像与语言表示，后者通过 flow matching 生成连续的未来动作。最值得理解的是，这两组权重怎样通过 attention 交换信息，以及为什么模型需要多次生成计算，却仍然能用于高频控制。训练上，作者还将大规模、多样的机器人数据与面向具体任务的高质量 post-training 区分开来。

背景

OpenVLA 将连续动作离散为 token，再像生成文本一样逐个预测。这个接口容易复用语言模型，但机器人动作与文字有不同需求：动作通常是连续数值，一次控制可能包含双臂的很多关节，还需要在较高频率下平滑执行。

如果未来 50 个时间步、每步十几个动作分量都逐 token 输出，串行生成就会变长。另一方面，在同一场景下可能有不止一种合理操作方式，直接预测一组固定数值，也未必能表达这种动作分布。

π0\pi_0π0​ 的选择是保留 VLM 的视觉语言知识，并为连续动作增加生成式建模。作者使用 action chunking 一次预测未来一段动作，再通过 conditional flow matching 学习条件动作分布。整个方法同时包括结构和数据配方：模型需要先见过足够多的机器人交互，再通过目标任务的数据学会更熟练的执行方式。

整体框架

原论文 Fig. 3。图像与语言进入预训练 VLM，机器人状态和带噪动作进入 action expert，两部分通过 attention 交换信息。

训练从 PaliGemma 初始化的 VLM 出发，加入机器人本体状态与动作输入输出，并在跨机器人数据混合上训练。得到 base policy 后，可以直接输入语言命令执行，也可以再用具体任务数据 post-train。

这里需要区分两次“预训练”：PaliGemma 已经经过互联网图文训练，π0\pi_0π0​ 又在此基础上做机器人数据预训练。后文比较“没有机器人预训练”时，不一定意味着连图文初始化也一起去掉。

模型

输入与动作

作者希望学习：

p(At∣ot),At=[at,at+1,…,at+H−1].p(\mathbf{A}_t\mid\mathbf{o}_t), \qquad \mathbf{A}_t=[\mathbf{a}_t,\mathbf{a}_{t+1},\ldots,\mathbf{a}_{t+H-1}]. p(At​∣ot​),At​=[at​,at+1​,…,at+H−1​].

At\mathbf{A}_tAt​ 是从机器人时刻 ttt 开始的未来动作 chunk，本文使用 H=50H=50H=50。条件观察包含多路 RGB 图像、语言与关节状态：

ot=[It1,…,Itn,ℓt,qt].\mathbf{o}_t=[\mathbf{I}_t^1,\ldots,\mathbf{I}_t^n,\ell_t,\mathbf{q}_t]. ot​=[It1​,…,Itn​,ℓt​,qt​].

Iti\mathbf{I}_t^iIti​ 是第 iii 路相机，通常有两到三路；ℓt\ell_tℓt​ 是语言指令；qt\mathbf{q}_tqt​ 是机器人关节角等本体状态。视觉编码器把图像转换成 patch 特征，文字经 tokenizer 和 embedding 得到文本特征，状态向量则通过线性层进入 Transformer。

动作也被称为 token，但这里的一个 action token 对应 一个机器人时间步的完整连续动作向量。它不是一个关节值的离散词表编号。H=50H=50H=50 就对应 50 个动作位置，每个位置内部仍有多个连续分量。

Flow matching

我们先只看动作生成。训练时已经知道真实 chunk At\mathbf{A}_tAt​，并采样一份相同形状的标准高斯噪声 ϵ\epsilonϵ。作者在噪声与真实动作之间构造插值：

Atτ=τAt+(1−τ)ϵ,ϵ∼N(0,I),τ∈[0,1].\mathbf{A}_t^\tau=\tau\mathbf{A}_t+(1-\tau)\epsilon, \qquad \epsilon\sim\mathcal{N}(\mathbf{0},\mathbf{I}), \qquad \tau\in[0,1]. Atτ​=τAt​+(1−τ)ϵ,ϵ∼N(0,I),τ∈[0,1].

这里有两种时间：下标 ttt 是机器人实际控制的时间，上标 τ\tauτ 是一次动作生成内部的 flow 时间。τ=0\tau=0τ=0 时完全是噪声，τ=1\tau=1τ=1 时到达示范动作。机器人在物理世界里前进一步，与生成算法沿 τ\tauτ 移动一步，是两件事。

原文 Sec. IV 的高斯路径描述将协方差写为 (1−τ)I(1-\tau)\mathbf{I}(1−τ)I，但同段的实际采样式使用噪声系数 (1−τ)(1-\tau)(1−τ)，对应的条件协方差应为 (1−τ)2I(1-\tau)^2\mathbf{I}(1−τ)2I。两处记号不一致；上面的插值与后续速度目标采用论文给出的实际采样式。

沿着这条插值路径，对 τ\tauτ 求导得到速度：

dAtτdτ=At−ϵ.\frac{d\mathbf{A}_t^\tau}{d\tau}=\mathbf{A}_t-\epsilon. dτdAtτ​​=At​−ϵ.

因此，训练样本可以提供一个明确的方向目标 u(Atτ∣At)=At−ϵ\mathbf{u}(\mathbf{A}_t^\tau\mid\mathbf{A}_t)=\mathbf{A}_t-\epsilonu(Atτ​∣At​)=At​−ϵ。模型接收带噪动作、生成时间以及观察条件，预测向量场 vθ\mathbf{v}_\thetavθ​，使用原文的 conditional flow matching 目标：

Lτ(θ)=Ep(At∣ot),q(Atτ∣At)∥vθ(Atτ,ot)−u(Atτ∣At)∥2.L^\tau(\theta)= \mathbb{E}_{p(\mathbf{A}_t\mid\mathbf{o}_t),q(\mathbf{A}_t^\tau\mid\mathbf{A}_t)} \left\| \mathbf{v}_\theta(\mathbf{A}_t^\tau,\mathbf{o}_t) -\mathbf{u}(\mathbf{A}_t^\tau\mid\mathbf{A}_t) \right\|^2. Lτ(θ)=Ep(At​∣ot​),q(Atτ​∣At​)​∥vθ​(Atτ​,ot​)−u(Atτ​∣At​)∥2.

原式把 τ\tauτ 的条件输入隐含在网络构造中；实现时，它经过正弦编码与 MLP，和带噪动作一起形成 action embedding。每个训练样本只需抽取一个 τ\tauτ 来构造监督。作者使用偏向低 τ\tauτ、即高噪声区域的时间采样分布，而非均匀地覆盖所有时间。

这里的监督与 DDPM 的噪声预测有区别：π0\pi_0π0​ 预测的是插值路径的速度 At−ϵ\mathbf{A}_t-\epsilonAt​−ϵ，不是直接把加入的 ϵ\epsilonϵ 作为输出目标。两者都能从噪声逐步生成连续变量，但采样公式与时间方向要按各自定义理解。

还有一个容易混淆的地方：虽然每对训练动作与噪声之间的插值是直线，网络在给定 Atτ,ot,τ\mathbf{A}_t^\tau,\mathbf{o}_t,\tauAtτ​,ot​,τ 时，并不知道背后是哪一条样本路径。平方损失让它学习这些路径在当前输入下的条件平均速度。不同位置的平均方向可以不同，因此最终学到的生成轨迹并不要求都是同一条直线。

Action expert

直接让整个大 VLM 在每一个 flow 步骤上重复处理全部内容，会有较高计算开销。作者为新加入的机器人状态与动作，设置一组较小的 Transformer 权重，称为 action expert。

模型有两套参数：图像和语言 token 使用从 PaliGemma 初始化的大主干；机器人状态与带噪动作 token 使用从零初始化的 action expert。它们在各层 self-attention 中交互。不同 expert 的隐藏宽度可以不同，只需要注意力交互所需的投影维度能够匹配。

这不是先由 VLM 生成一段文字，再把文字送给一个独立动作网络；动作位置能够通过多层 attention 读取视觉语言信息。它也不是根据内容动态挑选若干 expert 的路由系统，本文按 token 所属模态分配参数。

作者使用约 3B 的 PaliGemma，并添加约 300M 参数的 action expert，总计约 3.3B。较小的 expert 减少后续反复更新动作时的计算，但模型能力仍来自视觉语言与机器人数据的联合训练，不能将大主干理解成始终冻结的外部特征服务。

注意力

输入被分为三个块：

块 内容 可以读取的块
视觉语言 多路图像和语言指令 视觉语言
本体状态 qt\mathbf{q}_tqt​ 视觉语言、本体状态
动作 Atτ\mathbf{A}_t^\tauAtτ​ 的 50 个位置 全部块

每个块内部是双向 attention，块与块之间是因果关系。动作位置可以同时读取整个动作 chunk，所以未来第 20 步与第 30 步的候选动作能够交换信息；它们不必像文本一样依次生成。

视觉语言块不能读取状态和带噪动作，这减少了对原有 VLM 输入处理方式的扰动。状态块也不能读取动作，因而在一次 chunk 生成过程中，视觉、语言和状态的 key/value 都不随 τ\tauτ 改变，可以缓存。

这就把“一次获取观察”和“多次更新带噪动作”分开了：观察前缀只算一次，后面每一步 flow 只重新计算动作部分。缓存成立的关键是这些前缀特征没有通过 attention 反向依赖变化中的动作。

推理

没有真实动作时，先采样 At0∼N(0,I)\mathbf{A}_t^0\sim\mathcal{N}(\mathbf{0},\mathbf{I})At0​∼N(0,I)，再从 τ=0\tau=0τ=0 向 111 积分。本文用 forward Euler：

Atτ+δ=Atτ+δvθ(Atτ,ot).\mathbf{A}_t^{\tau+\delta} =\mathbf{A}_t^\tau+\delta\mathbf{v}_\theta(\mathbf{A}_t^\tau,\mathbf{o}_t). Atτ+δ​=Atτ​+δvθ​(Atτ​,ot​).

实验使用 10 步，δ=0.1\delta=0.1δ=0.1。每次先估计当前方向，再按步长更新整个动作 chunk，最终得到 50 步连续动作。真实动作与生成用的噪声差，只在训练时用来构造监督；部署时使用的是模型学到的向量场。

生成 50 步，不代表每次一定执行完 50 步。附录给出的控制方式是：20 Hz 的 UR5e 与 Franka 每执行 16 步、约 0.8 秒重新推理；其余 50 Hz 平台每执行 25 步、约 0.5 秒重新推理。每个执行区间内部按动作序列开环运行，下一次推理才利用新的图像修正。

所以需要同时区分预测长度、实际执行长度和生成计算时间。 50 Hz 是动作执行频率，不能解释为整个 VLM 每秒重新读取图像并推理 50 次。

数据与训练

预训练与 post-training

作者自己的数据来自 7 种机器人配置和 68 类任务，覆盖单臂、双臂及移动操作，约 10,000 小时、903M 个时间步；训练混合中还加入 OXE、BridgeData V2 与 DROID 等开放数据。

不同平台的状态和动作维度不同，作者将它们补零到统一的最大维度 18；相机不足三路时屏蔽缺失图像槽位。这让一个网络能够接收不同形状的机器人样本，但没有把各机器人的关节自动变成完全相同的物理语义。跨机器人迁移仍需由训练数据建立关联。

为防止数据量大的任务占据过多采样，任务与机器人组合的采样权重按样本数 nnn 的 n0.43n^{0.43}n0.43 设置。指数小于 1，意味着样本更多的组合仍然更常见，但不按原始数据量同比增长。

预训练希望覆盖多样状态、动作和纠正方式，post-training 则使用更窄、更高质量的数据，形成流畅且一致的目标任务策略。可以把二者的作用理解为：前者扩展“遇到哪些情形时知道能怎么做”，后者强调“这项任务希望怎样完成”。

只用整洁、成功的目标任务示范，可能缺少偏离后的恢复状态；只依赖广泛预训练，又未必学到足够稳定的目标任务习惯。作者用后面的对照研究这种组合。这是机器人数据上的分阶段监督训练，不是通过任务奖励进行在线强化学习。

语言与高层策略

训练标签不仅包含任务名称，也包含约两秒一段的细粒度语言标注。例如总目标是清理桌子，局部指令可以是“拿起纸巾”“把纸巾放进垃圾桶”。

因为低层策略接受语言，复杂任务还可以由一个额外的高层 VLM 分解，再把子任务指令送给 π0\pi_0π0​。它与人直接提供子指令、只给总任务描述，是不同实验设置。观看长任务演示时，需要看清是否使用了高层策略，不能把所有规划能力都归给单个低层动作模型。

实验

Base policy

作者先评估不做目标任务 post-training 的模型，测试折衬衫、清理桌面、装购物袋和从烤面包机取面包等任务。这些任务本身在预训练范围内，因此这里的 out-of-box 主要表示直接使用 base policy，不代表全部都是从未见过的任务。

指标是按任务规则归一化后的完成度，完整成功为 1，部分完成可以取得分数；每种方法、每个任务进行 10 次试验。例如清理桌面的得分与正确放置的物体比例有关，不能一概当成整任务的二元成功率。

作者将 OpenVLA 和 Octo 在同一机器人数据混合上继续训练。完整 π0\pi_0π0​ 训练 700k 步，同时还报告一个 160k 步版本，与 OpenVLA 的 160k、Octo 的 320k 步对照，见 Fig. 7。较短训练版本也表现较好，但更新次数相同或更少，不表示不同架构的精确 FLOPs 完全相同。

论文还比较了约 470M 的 π0\pi_0π0​-small。它不使用 PaliGemma VLM 初始化，但视觉和文本编码器仍使用各自的预训练组件，结构与容量也有多处变化。它提供了一个较小、没有 VLM 主干初始化的基线，不能被视为只移除某一个预训练因素的严格单变量消融。

语言遵循

语言实验在清理桌面、摆桌和装袋上，比较只给总任务、由人给中间指令，以及由高层 VLM 给中间指令。Fig. 9 中，π0\pi_0π0​ 能从更具体的人类指令中获得明显帮助，高层模型指令也能改善整体表现；π0\pi_0π0​-small 对这些指令的利用较弱。

这支持视觉语言初始化与模型规模对语言条件使用的帮助，但仍受前面提到的容量和结构差异影响。尤其是“能听懂子任务”与“能独立选择所有子任务”是不同能力，需要由对应实验分别判断。

新任务适配

作者再用不同数量的示范，微调到叠碗、折毛巾、操作微波炉、更换纸巾卷和用 Franka 收纳抽屉等任务，见 Fig. 10–11。任务按与预训练行为的相似程度划分，检查模型能否利用已有技能学习新动作。

这一组中，OpenVLA 和 Octo 从各自公开的 OXE 预训练 checkpoint 出发，再使用目标任务数据；ACT 和 Diffusion Policy 直接用目标任务数据训练。因此它与上一组“共同数据混合”的比较不同。

作者还比较 π0\pi_0π0​ 是否经历机器人数据预训练。总体上，预训练对部分少数据任务尤其有帮助，但收益随任务和数据量变化，并不是每条曲线都随数据增加严格单调。这也提示我们，增加数据的数量与增加合适的策略覆盖，需要分开研究。

复杂任务

最后一组通过 post-training 处理折叠成堆衣物、移动取放、清理拥挤餐桌、组装纸箱、打包食品与装鸡蛋等任务，执行可能持续数分钟。Fig. 13 比较完整训练、仅 base policy，以及只使用目标数据的版本。

完整流程在这些任务中通常更好，复杂任务尤其受益于机器人预训练。但结果仍按部分完成度计分，完整模型在所有任务上取得超过一半的最大得分，不代表所有任务的完整成功率都超过 50%。部分任务还使用高层语言策略辅助。

核心点和不足

π0\pi_0π0​ 把 VLA 的接口从“视觉语言模型生成离散动作词”扩展成“视觉语言模型为连续动作生成提供条件”。Action expert 保留生成分布的表达能力，双向动作 attention 一起组织未来多个动作，块状 attention 则让稳定观察与反复更新的动作可以分开计算。

数据配方同样重要。跨任务预训练与目标任务 post-training，分别提供覆盖和执行习惯；模型结构本身无法凭空补出缺失的恢复行为。论文还没有全面分离数据类型、采样权重和多机器人混合各自的贡献，何种数据能可靠带来正迁移，仍是开放问题。

此外，生成一个 chunk 后仍有开环执行区间；环境中出现快速变化时，要等重新观察后才能调整。长期任务表现也尚不稳定，一些结果依赖高层指令。其跨机器人实验主要覆盖操作平台，不能直接推广为对任意机器人形态和任务的统一控制能力。

总结

π0\pi_0π0​ 先从图像、语言与本体状态构造条件，再用 action expert 从噪声出发，通过 10 次 flow 更新生成 50 步动作；执行其中一段后，读取新观察继续生成。训练则先用广泛机器人数据建立 base policy，再用高质量任务数据形成更熟练的行为。

与 OpenVLA-OFT 对照，可以看到两种动作头取舍：OFT 用一次前向的连续回归获得较低延迟，π0\pi_0π0​ 用迭代向量场表达条件动作分布，再通过较小动作网络和缓存控制成本。下一步值得继续追踪的是，同一观察下的动作多模态到底有多重要，以及更快生成、更短执行区间与稳定控制之间怎样平衡。
