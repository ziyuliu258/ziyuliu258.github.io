论文阅读：VIMA - General Robot Manipulation with Multimodal Prompts

发表于2026-11-05|更新于2026-11-05
|总字数:4.8k|阅读时长:15分钟|浏览量:—

引：VIMA 把“按语言操作”“达到目标图像”“观看一次示范”“根据图片学习新概念”等任务，统一为 文字与图像交错的 multimodal prompt。模型再将画面拆成 object tokens，用 cross-attention 持续读取任务条件，生成机器人动作。它最有启发的地方，是任务接口、对象表示和泛化评估怎样配合，而不是单纯把一个语言模型接到机械臂上。

背景

假设要让机器人把一个指定杯子放进盒子。我们可以说“把红杯子放进盒子”，也可以直接提供杯子的照片。如果希望得到某种摆放结果，给出目标桌面的图片可能更清楚；如果要复现一段移动方式，几帧示范又比一句描述更直接。

这些任务都在要求机器人根据条件行动，但传统方法往往为语言指令、目标图像和视频示范分别建立接口与模型。VIMA 的出发点是：既然文字和图像都能变成 token，能否把这些条件统一放在一串 prompt 中，再用同一个策略完成操作？

作者不仅提出模型，还构建 VIMA-Bench，为不同条件形式与不同泛化难度提供训练和测试。方法的一个关键选择，是先把图像拆成对象，再交给策略，而不是要求控制模型直接从整张画面的 patch 中同时学会找物体和决定动作。

多模态提示

作者把长度为 lll 的 prompt 定义为：

P=[x1,x2,…,xl],xi∈{text,image}.\mathcal{P}=[x_1,x_2,\ldots,x_l], \qquad x_i\in\{\text{text},\text{image}\}. P=[x1​,x2​,…,xl​],xi​∈{text,image}.

这里的 xix_ixi​ 是任务条件中的文字或图像片段，后面还会经过各自的 tokenizer。视频示范可以按时间顺序放入多帧图像，因此也能接入同一个形式。

原论文 Fig. 1。目标图像、示范片段、新概念和操作约束都可以放进交错的图文提示。

比如“把 [杯子图片] 放进 [容器图片]”，用图像直接指定目标；“将物体摆成 [桌面图片]”，用图像提供结果；“这是 dax：[物体图片]，把 dax 放进盒子”，则在当前 prompt 内建立一个新词与对象的对应。

这些例子并不都意味着模型在推理时更新了权重。新概念 grounding 可以通过读取当前上下文完成；一次示范也只是当前任务的条件。能否根据这些条件正确行动，要在训练过的任务结构与未见组合上分别检验。

作者整理了六类任务：简单物体操作、视觉目标到达、新概念 grounding、一次视频模仿、视觉约束满足，以及视觉推理。类别可以重叠，例如一个视频既能展示新动作，也能解释一个新词。统一的是输入接口，不是把所有任务的语义都变成同一种问题。

VIMA-Bench

环境与数据

VIMA-Bench 基于 Ravens 与 PyBullet，使用 UR5 机械臂，观察包含正面和俯视两路 RGB 图像，以及表示末端工具类型的信息。任务使用吸盘抓放或刮板推动等高层技能，每个动作由两个末端位姿参数化。

例如 pick-and-place 的两个位姿分别指定在哪里抓取、在哪里放下；push 的两个位姿指定推动起点与终点。底层运动由技能执行器完成，所以策略的一步可以包含一段机械臂运动。它与直接每 20 ms 输出一次关节控制量的 VLA，动作抽象层次不同。

基准提供 17 个任务模板，通过替换对象、纹理和摆放生成大量实例。4 个模板保留作新任务测试，其余 13 个训练任务各生成 50,000 条成功示范，共 650,000 条。摘要中的 600K+ 是这一数量的概括。

示范来自可以访问物体精确状态与任务解释的脚本 oracle。环境也提供分割和边界框，用来训练、检查对象检测；策略正常评估时使用检测器从图像取得对象，而不是默认直接读取全部真实物体状态。

泛化层级

原论文 Fig. 2。四级测试逐步改变物体摆放、属性组合、对象，以及任务模板。

作者将评估拆成四级：

级别 测试改变了什么 需要检查的能力
L1 prompt 与训练相同，物体摆放改变 根据当前观察定位与执行
L2 对象和纹理都见过，但组合未见 重组已有属性
L3 prompt 与环境中出现新对象、纹理 迁移到新视觉内容
L4 新任务与新 prompt 模板 迁移任务结构与操作规则

比如训练中见过黄三角形和蓝方块，L2 可以测试蓝三角形；L3 则可能引入新的形状或纹理；L4 不只换物体，还可能改成按相同纹理收集所有物体的规则。

四级测试都不再为对应测试任务微调策略，论文因此称为 zero-shot generalization。这里并不表示训练中从未见过相关对象、技能或语言，未见因素要由具体层级确定。

每个任务按二元条件判断成功，不提供部分奖励；测试时计算多个 episode 的成功比例，再对任务平均。与 π0\pi_0π0​ 的部分任务完成度相比，这是不同的计分方式。

VIMA

策略

作者学习的策略为：

π(at∣P,H),H=[o1,a1,o2,a2,…,ot].\pi(a_t\mid\mathcal{P},\mathcal{H}), \qquad \mathcal{H}=[o_1,a_1,o_2,a_2,\ldots,o_t]. π(at​∣P,H),H=[o1​,a1​,o2​,a2​,…,ot​].

P\mathcal{P}P 指定要完成什么，H\mathcal{H}H 是已经发生的观察与动作。策略根据二者输出当前动作 ata_tat​，执行后把新观察追加到历史，再继续。

原论文 Fig. 3。左侧编码任务条件，右侧对交错的观察、动作历史做序列建模，通过交替的 cross-attention 与 causal self-attention 预测动作。

这里的自回归首先发生在环境交互的时间轴上：根据已经发生的历史预测下一步。它没有要求将当前动作的每个坐标都作为一个语言 token 串行生成，后面的动作头会直接解码多个分量。

对象 token

输入图像有两种情况：一张完整桌面场景，或者一个单独物体的参考图。对于完整场景，作者使用在任务域内微调的 Mask R-CNN，取得各对象的边界框与裁剪图。

每个对象由两部分描述：

  • 边界框 [xcenter,ycenter,height,width][x_{\mathrm{center}},y_{\mathrm{center}},\mathrm{height},\mathrm{width}][xcenter​,ycenter​,height,width] 归一化到 [0,1][0,1][0,1]，经 MLP 得到空间特征；
  • 对象裁剪图先补成正方形、缩放到 32×3232\times3232×32，再由一个从零训练的小 ViT 得到外观特征。

将两部分拼接并映射到 token 维度，就得到一个 object token。单物体参考图使用同样的编码器，只把边界框换成约定的 dummy box。检测器预测的类别名称不作为策略输入，物体信息主要由裁剪外观和位置表示。

举个例子，当前画面里检测到一个黄色块和一个花纹容器，就产生两组外观与位置特征。模型不必先从整张图像的大量背景 patch 中找出这两个对象，能直接比较参考图与候选物体、读取它们的相对位置。对象数量不同，token 数量也可以不同。

两路观察按正面、俯视的顺序组织对象 token，并结合末端工具类型构成 observation tokens。过去执行的动作则经过 MLP 编码，插入观察之间。由此，控制器处理的是“若干对象—动作—若干对象—动作”的历史，而不是只看一张当前截图。

这种表示同时引入了一个依赖：如果检测器漏掉目标，后面的策略可能根本接收不到相应对象。因此作者训练检测器时偏重高召回率，并在策略训练中随机注入假阳性对象，让模型学会忽略多余检测。这个增强主要对应多报对象的情况，不等于已经解决所有漏检与遮挡问题。

Prompt 编码

文本片段使用 T5 tokenizer 与词 embedding，图像片段先变成 object tokens，再通过 adapter MLP 对齐输入维度。将这些视觉与文字 token 按 prompt 的顺序交错排列，交给预训练 T5 encoder。

T5 原本在文本上训练，视觉部分通过新加入的映射接到它的输入空间，保留其已有的语言知识。实现细节采用 T5-base，主要冻结预训练层， 只微调最后两层，并使用分层学习率衰减，见 Appendix C.2。不能只根据正文的概括，把整个 T5 都写成完全冻结。

编码后的 prompt 保留为一个序列。比如参考对象、新词定义和目标容器可以位于不同位置，控制器在不同交互步骤都能重新读取这些信息，而不需要预先把整个任务压成一个全局向量。

条件注入

控制器使用交替的 cross-attention 与 causal self-attention。前者读取任务，后者组织已发生的交互历史。

将 prompt 编码成 KP,VPK_{\mathcal{P}},V_{\mathcal{P}}KP​,VP​，从历史产生 query QHQ_{\mathcal{H}}QH​，一次 cross-attention 为：

H′=operatornamesoftmax(QHKPTd)VP,\mathcal{H}'=operatorname{softmax}\left( \frac{Q_{\mathcal{H}}K_{\mathcal{P}}^{\mathsf T}}{\sqrt d} \right)V_{\mathcal{P}}, H′=operatornamesoftmax(d​QH​KPT​​)VP​,

其中 ddd 是注意力特征维度。我们可以把历史中当前需要决策的位置看成一个 query：它根据自己已有的信息，决定读取任务中的哪些位置，再把读出的条件内容用于后续计算。模型有残差连接，并重复交替两类 attention，而不是只做这一次公式里的操作。

例如，任务是“按示范顺序移动三个物体”。第一步需要读取第一个对象与目标位置，执行后再根据历史进度读取后面的条件。Prompt 独立保存为 key/value 序列，使任务条件在不同深度、不同步骤都能被直接访问。

这与把 prompt 和历史一次拼起来、完全用 decoder-only self-attention 处理，是两种条件组织方式。哪种更好需要放回具体模型和数据比较，不能从结构上直接断言 cross-attention 对所有 VLM 都更优。

动作与训练

Decoder 的输出特征进入一组动作头，预测两个末端位姿所需的离散位置和旋转分量，再映射回连续执行参数。附录中 x、y 坐标分别使用 50、100 个区间，旋转分量使用 50 个区间。两个位姿独立建模，分量由多个分类头输出。

对于一个真实的 pick-and-place 动作，网络提供的是抓取位姿与放置位姿；技能执行器再负责完成运动。因此一个策略动作的离散化，与 OpenVLA 的逐标量 next-token 生成在实现上不同，也与 π0\pi_0π0​ 输出连续高频动作 chunk 不同。

训练使用 behavior cloning。给定长度为 TTT 的专家轨迹，优化负对数似然：

min⁡θ∑t=1T−log⁡πθ(at∣P,H).\min_\theta\sum_{t=1}^{T} -\log\pi_\theta(a_t\mid\mathcal{P},\mathcal{H}). θmin​t=1∑T​−logπθ​(at​∣P,H).

每个 ttt 的历史只包含当前及过去可用的观察、动作，监督标签是该步专家动作。训练在已有数据集上进行，不访问模拟器开展在线策略优化；模型选择依据留出验证集，交互式测试时才让策略真正操作环境。

部署时也没有脚本 oracle 提供正确物体和目标位置，模型要根据图像、prompt 和自己的交互历史行动。虽然模型执行时会不断重新观察，训练过程仍属于离线模仿学习，不能因为测试有反馈就称为 DAgger 式在线训练。

实验

对照方法

作者将几种代表性结构适配到相同的多模态 prompt 与动作任务：

  • VIMA-Gato：用图像 patch 表示视觉观察，采用 decoder-only 序列模型；
  • VIMA-Flamingo：用 Perceiver 将视觉特征变成固定长度序列，通过 cross-attention 接入控制器；
  • VIMA-GPT：把图像编码为单个状态 token，用 decoder-only 处理任务与历史。

这些是作者为 VIMA-Bench 重建的架构变体，不能直接理解成原版 Gato 或 Flamingo 在其全部预训练条件下的机器人成绩。对照主要检验视觉表示与条件组织方式。

VIMA 在四级测试中都较好，L4 的优势尤其明显；但它从 L1 的 81.5 降到 L4 的 48.6，也说明新任务泛化仍然困难。单看“有没有超过基线”，容易忽略绝对成功率与不同难度之间的变化。

数据实验使用 0.1%、1%、10% 和全部示范。Appendix Table 11 中，约 92M 的 VIMA 使用 10% 数据时，L4 为 46.0；同组 VIMA-Gato 使用全数据为 12.2。这支持对象表示与条件机制在该基准上的数据效率，但基线数字应来自同一数据规模实验，不能与上一张模型规模表中的 92M 数字随意拼接。

像素基线也使用预训练并在相同域内图像上继续训练的 ViT，作者尝试控制额外视觉预训练信息的差异。它们仍具有不同的归纳偏置与数据处理方式，因此“对象表示减少了策略需要自行发现的结构”是有机制依据的解释，而非已经单独证明的唯一原因。

结构消融

Fig. 6 比较不同视觉 tokenizer。使用 Mask R-CNN 对象表示与使用 oracle 边界框的差距较小；直接使用图像 patch、全图 token 或 Image Perceiver 的结果更差。即便先检测对象，再用 Object Perceiver 压成固定长度，也会降低表现。

这个结果对理解 VIMA 很重要：在本文任务里， 保留逐对象、变长的序列 比先把对象再压成一组混合特征更有帮助。它不能推广为所有视觉任务都不应该池化；Idefics2 的图文问答使用不同数据、主干和目标，Perceiver 在那里有自己的收益。

Fig. 7 固定对象 tokenizer，只把条件注入换成拼接 prompt 的 decoder-only 结构。大模型下差距缩小，但小模型与较难的 L4 上，cross-attention 仍更有帮助。这个对照比直接比较两个完整系统，更接近检验“任务条件怎样进入控制器”。

T5 规模从 small、base 到 large 的消融没有显著差异；在这些任务与预算下，扩展语言 encoder 不是最明显的收益来源。它也提示我们，接口与对象表示可能比一味增加语言主干更先决定小数据任务能否学好。

任务差异

L4 的平均分还掩盖了明显的不均衡。Appendix Table 19 中，200M VIMA 在保留的任务 8 和 14 上分别为 100.0% 与 94.5%，任务 10 和 13 则为 0%。后两项涉及保留的示范模仿与视觉约束任务。

所以“能够迁移到新任务”在这组结果里主要由部分任务支撑，尚未覆盖所有类型的新规则。平均 48.6% 并不等于四类新任务都学会了一半。这类按任务拆分的检查，比只看总体提升倍数更能帮助决定下一轮需要增加什么训练内容。

核心点和不足

VIMA 的核心可以沿三条线理解：用多模态 prompt 统一任务条件，用对象 token 提供操作所需的中间结构，再用 cross-attention 让历史持续读取任务。这使“知道要操作哪个对象”和“根据执行历史决定下一步”能够在同一个模型中结合。

这种结构对界面或场景 agent 也有启发：文字指令、对象参考图与目标图可以共享条件接口；先获得可靠的对象及空间表示，有时能够减少低数据策略的学习负担。但是否应该引入检测器，要结合对象定义是否稳定、漏检代价，以及任务是否依赖细微接触或整图信息来判断。

论文的主要边界是仿真桌面与高层技能动作，尚未验证真实环境中的细粒度控制与广泛迁移。对象检测承担了部分视觉结构提取，脚本 oracle 提供了大量成功示范；这与开放环境下直接收集人类视频、训练低层控制，并不是相同难度。离线数据也没有显式覆盖策略自己产生的全部恢复状态。

总结

VIMA 先把文字、目标图与示范组织成一个 prompt，用对象编码和 T5 得到任务序列；再把当前对象观察与动作历史交给控制器，通过 cross-attention 读取任务，预测下一个高层技能动作，执行后继续观察。

它提供的一个有用研究视角是：通用策略的能力不仅取决于主干规模，也取决于 任务怎样表达、场景怎样分解、未见因素怎样被单独评估。与 OpenVLA 和 π0\pi_0π0​ 对照阅读时，可以继续追踪动作抽象层次、输入条件和训练分布的区别，再决定哪些结构适合迁移到新的 agent。
