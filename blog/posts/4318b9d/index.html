论文阅读：BlenderFORGE

发表于2026-11-20|更新于2026-11-20
|总字数:6.1k|阅读时长:20分钟|浏览量:—

引：BlenderFORGE 研究如何让多模态大模型在 Blender 中反复观察、执行代码和检查结果，直到把场景改成目标状态。论文的重点是将已有 3D 资产转化为编辑任务，再用可执行环境和可验证奖励训练交互式编辑 agent。

图 1：BlenderFORGE 从场景扰动中构造编辑任务，使模型学习视觉变化与 3D 编辑操作之间的对应关系。

背景

给定一个室内场景和一张目标图片，我们希望模型把椅子移到目标位置。对人来说，这可能只是选择椅子、拖动并检查结果；对多模态大模型来说，这个过程涉及几个连续的判断：先从场景描述和图片中找到对象，判断目标与当前状态的差异，再生成可执行的 Blender Python 代码，并观察执行后的场景，决定是否继续修改。

已有的 3D 编辑方法可以直接操作 mesh、NeRF 等表示；另一类工作则让大模型通过代码或工具操作 Blender。这类 agent 通常在推理时生成候选编辑，再利用渲染反馈进行筛选和修正。BlenderFORGE 关注的是与此互补的训练问题：能否把编辑过程中的经验用于更新模型，让开源模型本身学会更有效的交互？

困难在于，这需要大量带有起始状态、目标状态和编辑轨迹的数据，还需要一个能够执行代码、返回反馈并评价结果的环境。BlenderFORGE 因此将工作分成三部分：

  1. 从现有 3D 资产构造有起点和终点的编辑任务；
  2. 用 Blender Sandbox 执行代码、渲染反馈并读取场景状态；
  3. 先通过监督微调学习有效轨迹，再通过强化学习优化多轮交互。

方法

图 2：左侧从 3D 资产生成并筛选编辑任务；右侧通过教师轨迹和 Blender Sandbox 支持 SFT 与多轮 RL。

任务定义

论文将 3D 编辑定义为一个从起始场景到目标场景的转换问题。记起始状态和目标状态分别为 sss_sss​、sgs_gsg​。Agent 从 x0=ssx_0=s_sx0​=ss​ 出发，在第 kkk 步生成一段 Blender Python 动作 aka_kak​。环境执行后得到新场景：

xk+1=f(xk,ak).x_{k+1}=f(x_k,a_k). xk+1​=f(xk​,ak​).

执行之后，agent 可以请求当前场景的渲染图 I(xk+1)I(x_{k+1})I(xk+1​)，再决定下一步动作。设 T(u,v)\mathcal{T}(u,v)T(u,v) 表示从状态 uuu 到状态 vvv 的相对变换，论文的目标是：

minimize{ak}k=0K−1d(T(ss,xK),T(ss,sg)).\underset{\{a_k\}_{k=0}^{K-1}}{\text{minimize}}\quad d\left(\mathcal{T}(s_s,x_K),\mathcal{T}(s_s,s_g)\right). {ak​}k=0K−1​minimize​d(T(ss​,xK​),T(ss​,sg​)).

这里 ddd 衡量最终编辑与目标编辑之间的差距，具体采用什么距离取决于任务。也就是说，模型要从起始场景出发，让实际造成的变化尽量接近目标变化。

论文构造了四类任务：

  • Placement：编辑物体的平移和旋转，例如把椅子移到桌边并调整朝向。
  • Shape-Key：调整物体的 blend-shape 系数，例如改变角色表情或局部形变。
  • Lighting：编辑灯光颜色和强度等属性，例如将冷色灯光改成暖色。
  • Material：修改材质和 shader 参数，例如颜色、粗糙度或金属感。

Shape-Key 可以理解为一组预定义形变的控制系数。例如一个角色模型可能有“闭眼”和“微笑”两个 shape key；改变系数会改变顶点位置，但仍然操作同一个物体。论文中的 Shape-Key 任务是在给定的可编辑形变空间中匹配目标，而不是任意重建几何。

数据生成

训练 agent 首先需要大量“当前场景—目标场景”的编辑任务。直接寻找人工编辑记录比较困难，但已有 Blender 资产提供了另一种监督来源：场景中有哪些对象和参数是已知的，数据管线可以主动修改它们，并记录修改前后的状态。

图 3：以物体放置为例，数据管线筛选可编辑对象、施加扰动、布置相机并检查变化是否可见，最终导出起始与目标场景。

以 Placement 为例，管线可以先选择场景中的椅子，改变它的位置和朝向，再把扰动前后的场景组成任务对。因为变化由数据管线产生，系统知道哪些对象发生了什么变化，也能导出相应的场景状态供后续验证。

四类任务使用不同来源和扰动方式：Placement 使用 3D-FRONT 场景，筛选可移动对象，再采样受场景边界和碰撞条件约束的位置、旋转变化；Lighting 使用含有灯具和光源的 Infinigen 场景，修改光源颜色或强度；Shape-Key 使用整理过的带 shape key 资产，改变可编辑系数；Material 则使用整理过的 Infinigen 材质和 Blender Principled BSDF 材质，修改颜色、粗糙度、金属度等参数。

光有两个不同的场景还不够：模型要从图片判断变化，变化就需要在给定视角下可见。例如椅子虽然移动了，但始终被桌子挡住，那么目标图片就很难提供有效线索。因此，管线还需要选择相机、检查起点和终点的视觉差异，并过滤碰撞、变化不明显或渲染不稳定的样本。对于材质任务，作者还重复检查渲染，降低随机渲染噪声造成的影响。

最终，每个任务包含起始和目标场景、多视角渲染、文本指令以及结构化场景描述。这些信息用途不同：模型在交互中使用文本和图像观察任务；数据管线保存的真实状态则可用于过滤轨迹、计算奖励和评价结果。

Blender Sandbox

有了任务，模型还需要一个可以持续交互的 Blender 环境。Blender Sandbox 主要提供三种能力：执行模型生成的 bpy 代码；从指定相机渲染当前场景；导出结构化场景状态，用于奖励和评估。

模型使用的两个主要工具是 blender_code_executor 和 blender_preview_renderer。前者返回代码执行结果或错误信息，后者返回渲染图。模型可以自行决定什么时候修改、什么时候观察，不必每执行一段代码就固定渲染一次。

例如，模型先写代码移动椅子，执行成功后请求预览。如果发现椅子的朝向不对，它可以再生成旋转代码并重新观察。新一轮决策依赖的是 执行后的实际反馈：代码可能报错，也可能虽然执行成功，但得到的画面仍不符合目标。

为了让大量训练回合能够稳定运行，每个 episode 使用独立的 Blender 进程，避免不同任务共享场景状态；预览渲染放在独立的无界面 Blender 子进程中，并固定渲染设置，减少渲染崩溃对主场景的影响。管理服务监控实例，在崩溃或超时时回收并重启。轨迹生成、强化学习和评估使用同一套交互接口。

场景状态导出对训练尤其重要。图像能告诉我们场景看起来如何，但 Sandbox 还可以读取物体姿态、shape-key 数值、材质和灯光属性，使系统能够根据任务检查实际编辑结果。状态导出是验证机制的一部分，不应理解成模型直接获得了目标场景的完整参数。

评估指标

四类任务的尺度不同：移动椅子的几何距离，与修改灯光颜色造成的差异不能直接比较。论文先为不同任务定义距离，再根据起点与目标之间的原始差异进行归一化。

距离

视觉距离包括 Photometric Loss（PL） 和 N-CLIP。前者比较渲染图像的像素差异，后者用 1−CLIP similarity1-\text{CLIP similarity}1−CLIP similarity 衡量图像特征差异，两者都是越低越好。它们观察的是渲染结果，因此不同的场景状态也可能产生相似画面。

Placement 还使用 Part-aware Chamfer Distance（P-CD）。普通 Chamfer Distance 比较两组点云的最近点距离；P-CD 先按语义 part 分组，只比较同类 part，最后对各部分取平均：

P-CD(si,sj)=1∣P∣∑k=1∣P∣CD(sik,sjk).\text{P-CD}(s_i,s_j)=\frac{1}{|\mathcal{P}|}\sum_{k=1}^{|\mathcal{P}|}\text{CD}(s_i^k,s_j^k). P-CD(si​,sj​)=∣P∣1​k=1∑∣P∣​CD(sik​,sjk​).

其中 sks^ksk 是第 kkk 类语义部分的点云。这样做是为了让几何评价考虑组成场景的部分，而不是只看整个点云是否大致重合。例如，把椅子移到桌子的位置，整体空间占据也许仍有相似之处，但分组比较会进一步考察相同语义部分之间的差异。

另外，Sandbox 可以比较结构化状态：Shape-Key 使用系数向量的 L1 距离，材质和灯光使用对应属性差异；Placement 也可以检查被移动对象和姿态。

进度分数

设 sms_msm​ 是最终编辑后的场景，DDD 是某一种距离。论文定义进度分数：

PSD(sm;ss,sg)=clip(D(ss,sg)−D(sm,sg)max⁡(D(ss,sg),ϵ),0,1).\mathrm{PS}_{D}(s_m;s_s,s_g)=\mathrm{clip}\left(\frac{D(s_s,s_g)-D(s_m,s_g)}{\max(D(s_s,s_g),\epsilon)},0,1\right). PSD​(sm​;ss​,sg​)=clip(max(D(ss​,sg​),ϵ)D(ss​,sg​)−D(sm​,sg​)​,0,1).

分子表示最终场景与目标的距离，比起始场景与目标的距离减少了多少；分母则用起始差距归一化。ϵ\epsilonϵ 用于避免分母过小。

举个例子，如果起点到目标的距离为 101010，编辑后降到 444，那么进度分数是 0.60.60.6。如果编辑后距离增加到 121212，原始值为负，会被截断到 000。因此，没有改进和改得更差都会得到零进度；它们在这个分数上不会进一步区分。

成功率

对于 Placement 和 Shape-Key，论文还报告：

SR@τ=P(dm,gds,g≤τ).\text{SR@}\tau=P\left(\frac{d_{m,g}}{d_{s,g}}\leq\tau\right). SR@τ=P(ds,g​dm,g​​≤τ).

这里 dm,gd_{m,g}dm,g​ 是最终场景与目标的距离，ds,gd_{s,g}ds,g​ 是起始场景与目标的距离。SR@0.5 表示最终剩余差距不超过原始差距一半的任务比例，越高越好；SR@0.1 的要求更严格。这个指标衡量的是相对起点的改善程度，因此“成功”依赖所选距离和阈值，SR@0.5 并不要求最终场景与目标完全一致。

训练

监督微调

作者以 Qwen3-VL-8B-Thinking 为主要基础模型，先进行监督微调，让模型学会生成可执行的编辑轨迹。训练使用两种数据。

Trajectory-SFT 使用强模型作为教师。教师在 Sandbox 中完成四类任务，产生多轮轨迹，其中包含推理、工具调用和环境返回的信息。作者用任务指标过滤轨迹，再训练学生模型预测 assistant 的输出 token。

这一步向模型展示一条实际可执行的编辑过程：面对场景描述和目标图片，如何调用工具，如何根据报错或预览继续操作。不过，学生看到的是教师留下的轨迹；模仿已有轨迹，与自己在环境中探索并处理新结果仍然不同。

General-SFT 混入通用数据，以减轻任务微调对其他能力的影响。论文报告通用数据与任务轨迹的比例为 36:136:136:1，内容包括判断辅助场景是否比起始场景更接近目标的视觉问答、保持工具调用格式的 function-calling 样本，以及保持代码生成能力的编程题。其中视觉问答的标签由距离比较得到：

I(D(sc,sg)<D(ss,sg)).\mathbb{I}\left(D(s_c,s_g)<D(s_s,s_g)\right). I(D(sc​,sg​)<D(ss​,sg​)).

也就是说，如果辅助场景 scs_csc​ 比起始场景 sss_sss​ 更接近目标 sgs_gsg​，标签为真。这类数据训练模型比较场景与目标的距离，但并不要求模型自己完成整段编辑。

论文的实现中，SFT 只微调语言模型，视觉编码器和多模态投影层保持冻结。四类任务轨迹混合训练，得到一个通用编辑 agent。

AgentLoop-RL

SFT 让模型有了可执行的起点，但模型仍需要学习如何根据自己的动作和环境反馈完成任务。接下来，作者让模型在 Sandbox 中实际运行多轮交互，并使用 GSPO 进行强化学习。

每一轮的状态 sts_tst​ 包含初始任务上下文，以及之前的模型输出和工具响应。模型采样一个序列级动作：

at∼πθ(⋅∣st).a_t\sim\pi_\theta(\cdot\mid s_t). at​∼πθ​(⋅∣st​).

一个动作可以包含推理文本和工具调用。工具返回响应 ztz_tzt​ 后，对话状态更新为：

st+1=st⊕at⊕zt.s_{t+1}=s_t\oplus a_t\oplus z_t. st+1​=st​⊕at​⊕zt​.

这里的关键是：工具响应不是预先写好的教师轨迹，而是执行当前模型动作后由环境产生的结果。代码改变场景，预览返回当前图像，模型再基于新信息决定后续动作。

Episode 结束后，Sandbox 导出最终场景，并计算几类进度：rvisr_{\mathrm{vis}}rvis​ 表示渲染图像的视觉进度；rstater_{\mathrm{state}}rstate​ 表示结构化场景属性的进度，也考虑不该变化的属性；rgeor_{\mathrm{geo}}rgeo​ 表示 Placement 中基于 P-CD 的几何进度。

作者按任务选择更直接的验证信号：Placement 主要使用几何进度，Shape-Key 使用场景状态和视觉进度，Lighting 与 Material 主要使用视觉进度。不同成分按任务加权，得到任务进度奖励 rprog(sm)r_{\mathrm{prog}}(s_m)rprog​(sm​)。

现在还有一个探索问题：如果模型一开始连有效工具调用都很难生成，最终场景通常不会变化，进度奖励也就很难区分不同尝试。作者因此加入轨迹级辅助信号 A(τ)∈[0,1]\mathcal{A}(\tau)\in[0,1]A(τ)∈[0,1]，鼓励模型产生有效的可执行工具使用及可测量的场景变化。最终奖励是：

r(τ)=(1−λact)rprog(sm)+λactA(τ),0≤λact≪1.r(\tau)=(1-\lambda_{\mathrm{act}})r_{\mathrm{prog}}(s_m)+\lambda_{\mathrm{act}}\mathcal{A}(\tau),\quad 0\leq\lambda_{\mathrm{act}}\ll 1. r(τ)=(1−λact​)rprog​(sm​)+λact​A(τ),0≤λact​≪1.

辅助项帮助模型进入可执行的动作空间；由于它的权重很小，仅仅执行代码不能获得高奖励，任务质量仍主要由编辑进度决定。训练时每个 RL episode 最多进行 8 轮交互。

实验

设置

主测试集覆盖四类任务，每类包含 200 个测试任务。模型得到起始场景的文本信息、起始多视角渲染图，以及与之对应的目标渲染图，然后通过 Sandbox 工具进行多轮编辑。

论文将训练后的模型与各自的开源基础模型比较，也列出多个闭源模型的零样本结果作为参考。因 API 超时或服务器错误中断的 episode 会从对应模型的评估中排除；模型生成的代码错误则允许在该 episode 内继续尝试。因此，部分模型实际评估的任务数可能少于每类 200 个。

主要结果

在论文自己的测试集上，Qwen3-VL-8B 经过 BlenderFORGE 训练后，四类任务都有改善：

指标 基础模型 BlenderFORGE 训练后
Placement SR@0.5 ↑ 1.50% 36.00%
Shape-Key SR@0.5 ↑ 12.00% 20.00%
Lighting PL ↓ 43.0 17.1
Material PL ↓ 23.9 12.7

表中的 PL 采用论文的 ×10−3\times 10^{-3}×10−3 标度。Placement 的提升尤其明显：训练后，超过三分之一的任务使剩余 P-CD 降到起始差距的一半以内。

不过，这些指标反映的能力不同。Placement 和 Shape-Key 的 SR 使用几何或参数距离；Lighting、Material 在这里列出的是图像误差。它们共同说明训练改善了所报告的指标，但不能只凭某一项数字判断所有属性是否都被正确编辑。

以 GPT-5.2 为例，Placement 的 SR@0.5 为 62.76%，Shape-Key 为 39.27%。这说明即使模型有较强的通用推理和代码能力，把目标图片落实为正确的场景操作仍然困难；同时，闭源模型是论文中的零样本参照，与专门训练过的模型有不同的训练条件。

消融实验

作者在 Placement 上比较了不同训练阶段，所有行都使用 200 个任务：

训练阶段 SR@0.5 ↑ 平均交互轮数
基础模型 1.50% 9.29
仅 RL 8.50% 10.08
Trajectory-SFT 24.00% 8.01
Trajectory-SFT + General-SFT 25.50% 5.76
Trajectory-SFT + RL 21.00% 10.63
完整流程 36.00% 6.49

仅靠 RL 相比基础模型有改善，但低于 Trajectory-SFT。对这样的工具任务，先看到可执行的示范轨迹，能为后续交互提供一个有用的起点。

其次，RL 的作用依赖初始化和训练组合。Trajectory-SFT 直接接 RL 时，SR@0.5 从 24.00% 降到 21.00%；加入 General-SFT 后再做 RL，完整流程达到 36.00%。因此，不能简单说“只要加入 RL 就会更好”。论文展示的是完整训练组合在该实验中效果最好，而不是单独证明某一个阶段对所有设置都有正向作用。

最后，Trajectory-SFT + General-SFT 的平均轮数最少，完整流程使用更多交互换来了更高的编辑质量。轮数本身也不能独立代表效率：过早停止可能很快，但任务没有完成。

第二个模型与迁移

作者还在 Qwen3.5-9B 上使用同一套训练流程。在 BlenderFORGE 测试集上，Placement SR@0.5 从 3.00% 提高到 40.00%，Shape-Key SR@0.5 从 6.00% 提高到 27.50%。这说明训练框架的收益并不只出现在最初的 8B 模型上。

在独立的 BlenderGym 基准上，训练后的 Qwen3.5-9B 相比基础模型也有改善：

任务与指标 基础模型 BlenderFORGE 训练后
Placement SR@0.5 ↑ 20.00% 36.00%
Shape-Key SR@0.5 ↑ 10.26% 17.95%
Lighting PL ↓ 52.6 19.0

这里没有报告 Material：论文说明 BlenderGym 使用的旧版 Blender 与其材质编辑 API 调用不兼容。这个结果提供了跨基准的证据，但覆盖的仍是与训练任务相近的编辑类别。

作者还测试了训练中未包含的相机重新取景任务：20 个手写任务，每个任务对每个模型评估三次。训练后两个模型的有效率都达到 35.0%，高于各自基础模型，但仍只有约三分之一的结果满足有效性条件，且角度误差较大。因此，这提供了有限的跨任务迁移证据，离可靠的通用相机控制还有距离。

定性结果

论文中的成功轨迹展示了模型交替使用代码执行和预览：先检查或修改场景，再根据渲染结果继续调整。例如在材质编辑中，模型可以检查已有材质参数，修改相关属性，并通过预览观察纹理或外观的变化。

这类轨迹有助于理解数字背后的过程：最终结果不一定来自一次正确预测，也可能来自几次尝试和反馈。不过，成功案例本身不能代表平均表现，仍需要结合成功率、距离指标以及失败案例一起看。论文图 4 展示了代表性编辑结果，项目页面也提供了四类任务的演示。

讨论

可验证的交互

BlenderFORGE 的一个关键设计，是让 编辑动作、环境反馈和奖励共享同一个可执行场景。

在普通图像匹配里，我们可能只有起始图和目标图；在 Blender 中，系统还持有实际场景及其结构化属性。数据管线可以生成已知变化，Sandbox 可以执行模型代码，评估器又能从场景状态或渲染图中测量结果。三者连接起来后，模型可以反复尝试，而训练信号不必完全依赖人工逐轮标注。

不同验证信号解决的问题也不同。视觉距离能够覆盖灯光和材质外观，却可能受视角、遮挡或渲染影响；结构化状态更直接，但依赖能够读取和比较的属性。本文按任务使用不同信号，体现的是围绕具体编辑对象设计奖励，而不是存在一个对所有 3D 编辑都充分的统一指标。

任务范围

论文的四类任务建立在已知、可扰动且可验证的属性上。这使数据生成和训练更可控，但也限定了结果范围：Shape-Key 编辑是在已有系数空间内调整，不等同于开放式几何建模；Placement 是受约束的物体姿态修改，也不等同于任意场景搭建。

论文还指出，尽管做了去重，部分 Shape-Key 基础 mesh 仍在训练和测试划分中共享。因此，这部分结果应结合具体划分理解，不能全部解释为对未见过基础形状的泛化。

相机任务和 BlenderGym 测试说明模型可能迁移到训练设置之外，但相机控制的有效率仍然偏低。更复杂的组合式编辑、在多个约束之间规划，以及迁移到非 bpy 的工具环境，仍是后续问题。

奖励与目标

进度分数将不同任务的初始差距归一化，适合比较“完成了多少已有差距”，但它仍受所选距离约束。视觉上接近不一定意味着对象属性正确；相反，某些参数差异也可能在给定视角下不可见。

论文使用多视角、结构化状态和任务特定指标来缓解这些问题。任务扩大后，如何验证“改对了对象、保留了其他内容、满足了自然语言意图”，仍可能需要更丰富的监督。一个直接的后续方向是研究更开放的组合编辑任务：不仅改变一个已知属性，还要判断应该改哪些对象，以及如何检查未被请求修改的部分。

总结

BlenderFORGE 将 3D 编辑 agent 的训练组织成一条完整链路：

  1. 从已有 Blender 资产中扰动可编辑属性，构造起始与目标场景；
  2. 在隔离的 Sandbox 中执行代码、返回渲染，并导出状态用于验证；
  3. 用教师轨迹和通用数据进行 SFT，再通过多轮环境交互和进度奖励进行 RL。

它最有启发性的地方，是把 3D 软件中原本就存在的 可执行状态 用作训练资源：场景既是模型操作的对象，也是生成任务和验证结果的依据。实验显示，这种训练能显著改善所测模型在四类受控编辑任务上的表现，也能部分迁移到另一个基准；对于开放式建模和新的工具操作，当前证据仍然有限。
