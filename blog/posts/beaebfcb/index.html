论文阅读：What matters when building vision-language models?（Idefics2）

发表于2026-11-05|更新于2026-11-05
|总字数:4k|阅读时长:12分钟|浏览量:—

引：Idefics2 最值得读的地方，是作者把构建 VLM 时经常一起变化的选择拆开比较：预训练主干怎样选，图像怎样进入语言模型，哪些参数需要适配，以及视觉 token 应该保留多少。最后得到的 8B 模型固然重要，但对自己训练模型更有帮助的是这些选择之间的联系，尤其是 架构、可训练参数和训练稳定性需要一起考虑。

背景

我们可以先把 VLM 想成三个部分：视觉编码器从图像提取特征，语言模型处理文本并生成回答，中间再放一组连接两个模态的参数。看起来只要选一个 ViT、一个 LLM，再接上 projector 就能开始训练，但每一步其实都有不同做法。

例如，图像特征可以作为独立信息源，让文本在若干层中通过 cross-attention 读取；也可以直接变成一串视觉 token，与文本拼在一起交给语言模型。两种方案新增的参数、占用的序列长度，以及对预训练主干的适配需求都不同。如果只比较最终模型，很难知道性能究竟来自架构还是训练配方。

作者因此先研究设计空间，再用实验中得到的选择训练 Idefics2。阅读时可以把它分成两部分：前半篇是受控消融，后半篇是最终模型的数据与训练流程。前面的四项平均分，也不能与后面的单项 benchmark 分数混为一谈。

基本结构

本文讨论的多模态预训练，从已经训练好的视觉和语言主干出发，让它们学会一起处理图文。之后的 instruction fine-tuning 再用问答与任务数据，让模型按照用户指令作答。这里的“预训练”不意味着把视觉编码器和 LLM 都从零训练。

图来自原论文 Fig. 2。每张图像经过视觉编码器与连接模块，得到 64 个视觉 token，再与文本一起输入 LLM。

作者比较两种融合方式：

  • Cross-attention：在语言模型的层之间插入 cross-attention，文本特征作为 query，读取视觉特征提供的 key 和 value。
  • Fully autoregressive：把视觉特征投影到语言模型的输入维度，与文本 embedding 拼成一个序列，再由语言模型生成文本。

后一种方案中的 autoregressive，描述的是文本输出的生成方式。图像已经作为条件输入，不需要先把图像逐 token 生成出来。连接模块内部也可以使用 attention；所以“fully autoregressive”与“模型里完全没有 cross-attention 运算”不是一回事。

设计空间

这一部分默认训练 6,000 步，报告 VQAv2、TextVQA、OKVQA 和 COCO 四项任务的 4-shot 平均分，分别覆盖视觉问答、图中文字、外部知识和图像描述。平均分用于比较同一组消融，不能当成某个任务的成功率。

预训练主干

在固定模型规模、数据和训练更新次数的实验中，将语言主干从 Llama-1-7B 换成 Mistral-7B，平均分从 62.5 增加到 67.6。视觉侧从 CLIP-ViT-H 换成 SigLIP-SO400M，平均分从 57.4 增加到 60.7，见原论文 Table 1–2。

这说明多模态模型的收益，有一部分已经来自单模态主干本身。比较 VLM 时，需要先确认用了哪个视觉编码器、哪个语言模型，不能把所有提升都归给连接方式。

不过，视觉比较还改变了输入分辨率：CLIP 和 EVA-CLIP 使用 224，SigLIP 使用 384。因此这组结果支持作者选择这套主干配置，却没有单独分离编码器训练质量与分辨率的影响。参数更多也不自动对应更高分数：约 4.4B 的 EVA-CLIP 与约 400M 的 SigLIP，在这组任务上的表现接近。

架构与参数适配

先看原论文 Table 3：

架构 主干训练方式 平均分 ↑
Fully autoregressive，不使用 Perceiver 冻结 51.8
Fully autoregressive，使用 Perceiver 冻结 60.3
Cross-attention 冻结 66.7
Cross-attention LoRA 67.3
Fully autoregressive，使用 Perceiver LoRA 69.5

冻结主干时，cross-attention 更好。但它在这个配置中约有 2B 可训练参数，比另一种架构多约 1.3B；推理 FLOPs 也多约 10%。因此，前两种融合方法的冻结实验并不是相同可训练参数预算下的比较。

作者进一步尝试解冻全部参数。Fully autoregressive 方案出现 loss 发散，降低学习率和逐步解冻都没有解决作者遇到的稳定性问题。最后采用的办法是： 新初始化的连接模块正常训练，预训练参数通过 LoRA 适配。此时 fully autoregressive 的平均分从 60.3 增加到 69.5，并超过 cross-attention 的 67.3。

我们可以这样理解这个变化。冻结主干时，新增模块要把视觉特征变成一个固定语言模型已经能够使用的输入；允许主干适配后，视觉、语言与连接模块可以共同调整对接方式。LoRA 用一个低秩增量修改预训练线性映射，减少需要优化的参数与优化器状态，也在本文实验中改善了稳定性。训练后还可以把增量合并回原权重。

这里的经验结论是，架构优劣依赖训练方式。它也没有证明 LoRA 普遍优于 full fine-tuning，或直接解决所有小数据过拟合问题：稳定训练、拟合能力和泛化表现是需要分别检查的结果。

视觉 token

一张图像经过 ViT 后，通常会产生几百个 patch 特征。如果全部交给 LLM，每个图文样本就会占用很长的上下文；一段包含多张图像的文档，开销更加明显。

Idefics2 使用两层 MLP 将视觉特征映射到语言隐藏维度，再用 Perceiver resampler 压缩序列。它可以理解为一组可学习的查询向量：这些 query 通过 attention 读取原来的 patch 特征，经过若干层更新后，得到固定数量的视觉 token。

举个例子，原来有 729 个 patch 特征，设置 64 个 query，就得到 64 个输出 token。每个输出可以汇集多个位置的信息，内容由训练决定；它们不是简单挑选出的 64 个 patch，也不一定各对应一个独立物体。这里压缩的是进入 LLM 的序列长度，视觉编码器仍然需要先处理输入图像。

在冻结主干的对应消融中，使用 Perceiver 后平均分从 51.8 增加到 60.3，同时将视觉 token 从 729 个减到 64 个。另一组比较中，128 个 token 为 71.2，64 个为 71.7，见 Table 4。不同表格的训练配置有所变化，应在各自对照内理解；它们共同支持的结论是：在本文预算与任务中，更长的视觉序列没有持续带来收益。

分辨率与宽高比

读取一页扫描文档时，如果先强行缩成一个小正方形，细小文字会丢失，原来的版式比例也会改变。作者因此让视觉编码器接收保持宽高比、分辨率可变化的图像，并插值已有的位置 embedding，用 LoRA 适配视觉主干。

经过这一步，不同图像可以产生不同数量的 patch；Perceiver 再把它们压缩成固定数量的视觉 token。于是输入分辨率与 LLM 的图像序列长度可以分开调整：前者影响视觉侧能读到什么、要做多少计算，后者影响传给语言模型的信息容量与计算量。

Table 5 中固定方形图像的平均分为 73.1，保持宽高比的配置为 72.1。作者据此认为性能大体保持，同时获得分辨率选择的灵活性。它并不是一组“保持比例必然提高准确率”的实验。

图像切分

另一种增加细节的办法，是保留原图，再添加四个局部裁剪。每个局部图像单独编码，最后一张原始图像就变成了五份视觉输入。

这样，原图仍提供整体布局，四个局部提供更细的内容。每份输入产生 64 个视觉 token，总数就从 64 增加到 320。作者在 SFT 中仅对一半样本使用切分，使同一模型在推理时既能处理单图，也能处理五图版本。

这个设计给出了直接的计算取舍：普通图像可以只用全图，需要读小字时再增加局部图。它增加了视觉编码与 LLM 输入的开销，是否值得要看任务，后面的最终结果也反映了这种差异。

Idefics2

多阶段预训练

最终模型选择 SigLIP-SO400M 与 Mistral-7B-v0.1，组合后约为 8B 参数。数据分为三类：交错图文文档、图像描述对，以及 PDF/OCR 数据。

交错文档使用 OBELICS，让模型处理一篇文章中交替出现的多张图片和文本；图文对帮助学习图像内容与描述的对应；OCR-IDL、PDFA 和 Rendered Text 则提供文档、文字转写及字体背景变化。它们要求模型使用的视觉信息并不相同，混合起来也就不只是增加同一种 caption 数据的数量。

预训练分两阶段：

阶段 最大图像分辨率 数据采样比例
第一阶段 384 像素 交错文档 70%，图文对 30%
第二阶段 980 像素 交错文档 45%，图文对 35%，PDF 20%

第一阶段用较低分辨率节省计算，第二阶段加入需要读小字的文档，并提高分辨率上限。两阶段都训练连接模块，并通过参数高效方式适配预训练主干；这不是“先只训练 projector，再解冻主干”的两阶段划分。

作者使用 10−410^{-4}10−4 学习率，约遍历数据两轮，累计对应约 15 亿张图像和 2,250 亿文本 token。这里是训练期间处理的累计量，包含重复，不应理解成同样数量的独立图像。

文档能力还依赖分辨率与数据的配合。Table 7 在预训练 5,500 步后，再用 DocVQA 微调 500 步：不加 OCR 数据时，分辨率从 384 提高到 768，分数由 22.6 到 42.9；在 768 下加入 OCR 数据后，再到 49.9。小字首先要看得清，对应的监督也要提供出来。

指令微调

作者整理了 The Cauldron，把 50 个视觉语言数据集统一为问答形式，覆盖视觉问答、计数、OCR、文档、图表、几何、差异识别以及截图转代码等任务。相同图像有多个问答时，将它们组织成多轮对话；同时混入纯文本指令数据，并对训练与评估数据做去重。

这一阶段使用 DoRA，它是 LoRA 的变体；不能把预训练和 SFT 都笼统写成同一套 LoRA 配置。损失只计算回答 token，问题与图像作为输入条件。比如“图中金额是多少？”是用户提供的信息，模型被监督的是回答中的金额与结束标记，而不是复述问题。

论文还针对某些数据集重复训练多轮的情况，使用三种降低过拟合风险的办法：NEFTune 对 embedding 加噪，随机提高图像分辨率，以及在适用时打乱同一图像的多个问答轮次。最后一项有使用条件：互不依赖的问题可以换序，如果后一问依赖前一问的指代或回答，直接打乱就会破坏样本含义。

这些做法为小数据 SFT 提供了可检查的选项，但论文没有逐项证明它们分别贡献多少收益。实际训练时仍需结合验证集判断：模型记住了固定问题顺序，依赖特定图像尺寸，还是缺少目标任务所需的视觉监督。

TextVQA 从 70.4 增加到 73.0，其他几项基本没有提高。这正好解释了前面的取舍：更多局部视觉信息对读字有帮助，但不必然改善所有推理任务。

这张表与设计空间中的 4-shot 平均分评估不同，也与 base 模型的 8-shot 评估不同。模型训练阶段、提示方式和指标都要一起看，才能判断一项训练改动到底带来了什么。

对话适配

常见 benchmark 希望模型给出简短答案，而实际对话往往希望有解释。作者发现同一个 instructed 模型不容易同时满足这两种输出习惯，于是再用 LLaVA-Conv 和 ShareGPT4V 训练几百步，得到 Idefics2-chatty。人工盲评更偏好这个版本的交互回答。

这个阶段主要调整模型怎样组织回答。它提醒我们，生成更长、更像对话的文本，与获得更高的短答案评测分数，是两个需要分别选择数据与验证方式的目标。

核心点和不足

Idefics2 把图像理解分成了几处可以独立检查的环节：视觉编码器能否保留所需细节，连接模块怎样压缩与投影，语言模型是否能够适配这些输入，以及 SFT 数据是否教会了目标任务与回答方式。它提供的价值，是让“VLM 微调效果不好”能够被拆成更具体的问题。

它也有明确的证据范围。主干和架构实验只覆盖本文的数据、预算与任务；一些对照的参数量或分辨率不同。过拟合相关的增强没有完整的逐项消融，最终模型还使用了很大的训练规模。因此，不能只取出“64 个 token”“使用 LoRA”中的某一个选择，就预期复现最终模型的全部能力。

对于后续的具身模型，这篇文章更直接地解释了视觉语言底座怎样形成。要输出可靠动作，还需要动作监督、状态信息和环境交互；图文问答分数本身没有检验错误动作后的恢复能力。

总结

Idefics2 的流程是：选择预训练视觉与语言主干，用 MLP 和 Perceiver 将图像压成较短的视觉序列；通过图文、交错文档和 OCR 数据完成多模态预训练，再用 DoRA 和多任务问答数据做指令微调。图像切分则让同一模型在推理时选择不同的计算开销。

最值得带走的思路是， 信息怎样进入模型，与哪些参数能够适配这些信息，需要一起设计。接着读 Prismatic VLMs，可以比较另一组 VLM 设计实验；再读 Building and Better Understanding Vision-Language Models，可以继续追踪更完整的数据与训练配方。
