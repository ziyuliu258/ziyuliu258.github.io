论文阅读：LoRA: Low-Rank Adaptation of Large Language Models

发表于2026-10-31|更新于2026-10-31
|总字数:7.6k|阅读时长:30分钟|浏览量:—

引：Edward Hu、Yelong Shen 等人在这篇文章中提出 LoRA。全量微调会为每个下游任务保存一整份与预训练模型同样大的参数；LoRA 改为冻结预训练权重，只训练插在权重旁边的低秩分解。以 GPT-3 175B 为例，作者把可训练检查点从约 350GB 降到约 35MB，训练显存从 1.2TB 降到 350GB，部署时再把低秩更新加回原矩阵，因此不增加推理延迟。

输入 xxx 同时走两条支路：左边是冻结的预训练权重，右边是秩为 rrr 的可训练矩阵 AAA 和 BBB。两条输出相加得到 hhh。图来自原论文 Fig. 1。

问题

很多自然语言应用都是先在通用语料上预训练一个大模型，再把它适配到某个具体任务。设这个自回归语言模型是 PΦ(y∣x)P_\Phi(y|x)PΦ​(y∣x)，参数为 Φ\PhiΦ。下游数据是一组上下文和目标，Z={(xi,yi)}i=1,…,NZ=\{(x_i,y_i)\}_{i=1,\ldots,N}Z={(xi​,yi​)}i=1,…,N​。例如把自然语言问句写成 SQL 时，xxx 是问题和表结构，yyy 是 SQL；做摘要时，xxx 是文章，yyy 是摘要。

全量微调从预训练权重 Φ0\Phi_0Φ0​ 出发，沿梯度把条件语言建模的对数概率尽量变大：

max⁡Φ∑(x,y)∈Z∑t=1∣y∣log⁡(PΦ(yt∣x,y<t))\max_{\Phi}\sum_{(x,y)\in Z}\sum_{t=1}^{|y|}\log\left(P_{\Phi}(y_t|x,y_{<t})\right) Φmax​(x,y)∈Z∑​t=1∑∣y∣​log(PΦ​(yt​∣x,y<t​))

更新之后的参数可以写成 Φ0+ΔΦ\Phi_0+\Delta\PhiΦ0​+ΔΦ。问题出在 ΔΦ\Delta\PhiΔΦ 的大小：∣ΔΦ∣=∣Φ0∣|\Delta\Phi|=|\Phi_0|∣ΔΦ∣=∣Φ0​∣。GPT-3 的 ∣Φ0∣|\Phi_0|∣Φ0​∣ 大约是 1750 亿。每多一个任务，就要再存、再加载一份同等大小的模型。

作者因此把任务增量写成更小参数 Θ\ThetaΘ 的函数，ΔΦ=ΔΦ(Θ)\Delta\Phi=\Delta\Phi(\Theta)ΔΦ=ΔΦ(Θ)，并且 ∣Θ∣≪∣Φ0∣|\Theta|\ll|\Phi_0|∣Θ∣≪∣Φ0​∣。要优化的不再是整份 Φ\PhiΦ，而是 Θ\ThetaΘ：

max⁡Θ∑(x,y)∈Z∑t=1∣y∣log⁡(pΦ0+ΔΦ(Θ)(yt∣x,y<t))\max_{\Theta}\sum_{(x,y)\in Z}\sum_{t=1}^{|y|}\log\left(p_{\Phi_0+\Delta\Phi(\Theta)}(y_t|x,y_{<t})\right) Θmax​(x,y)∈Z∑​t=1∑∣y∣​log(pΦ0​+ΔΦ(Θ)​(yt​∣x,y<t​))

后面的方法就是给 ΔΦ\Delta\PhiΔΦ 选择一种低秩表示。在 GPT-3 175B 上，∣Θ∣|\Theta|∣Θ∣ 可以小到 ∣Φ0∣|\Phi_0|∣Φ0​∣ 的约 0.01%。

已有方法

少训练一些参数这件事并不新。作者重点比较当时两条常用路线：在网络里插入 adapter，或者直接学习输入侧的一段连续提示。两条路线都能缩小任务参数，但在延迟敏感的在线推理里各自有硬约束。

Adapter 加在 Transformer block 里面。Houlsby 等人的设计是每个 block 放两处，自注意力之后一处，MLP 之后一处；每一处都是先降维、经过非线性、再升维，然后接到残差上。Lin 等人的设计只在 MLP 和 LayerNorm 之后放一处。瓶颈维度可以很小，所以新增参数经常不到原模型的 1%，额外 FLOPs 看起来也不多。

真正的开销来自计算方式。大模型靠硬件并行把延迟压低，adapter 却要在原来的层后面串行执行。在线推理的 batch 经常就是 1。作者在单卡 GPT-2 medium 上测量了一次前向的延迟，硬件是 NVIDIA Quadro RTX8000，下表是 100 次的平均毫秒数。

另一条路线是改输入。Prefix-embedding 在输入前面放若干个不在词表里的特殊 token，只训练它们的 embedding。Prefix-layer 更进一步：每一层 Transformer 之后，这些特殊位置上的激活都换成可训练向量，不再使用前一层算出来的结果。可训练参数分别是 dmodel(lp+li)d_{\mathrm{model}}(l_p+l_i)dmodel​(lp​+li​) 和 L dmodel(lp+li)L\,d_{\mathrm{model}}(l_p+l_i)Ldmodel​(lp​+li​)，其中 lpl_plp​、lil_ili​ 是前缀和中缀 token 数，LLL 是层数。

这条路线有两个直接后果。特殊 token 占用的是模型的序列长度，留给真正任务文本的位置就变少。作者还观察到，可训练参数变多时，prefix 的效果并不单调变好；他们把具体任务结果放到 GPT-3 实验里再看。

方法

低秩更新

神经网络里的很多层都是一次矩阵乘法。这些权重矩阵本身通常是满秩的。Aghajanyan 等人曾经说明，预训练语言模型有较低的内在维度，即使先随机投影到一个小空间里，仍然能有效学习下游任务。作者把这个观察推到权重的变化上：适应过程中需要学习的 ΔW\Delta WΔW，本身也可能是低秩的。

对一个预训练矩阵 W0∈Rd×kW_0\in\mathbb{R}^{d\times k}W0​∈Rd×k，把它的更新限制成

W0+ΔW=W0+BA,W_0+\Delta W=W_0+BA, W0​+ΔW=W0​+BA,

其中 B∈Rd×rB\in\mathbb{R}^{d\times r}B∈Rd×r，A∈Rr×kA\in\mathbb{R}^{r\times k}A∈Rr×k，并且 r≪min⁡(d,k)r\ll\min(d,k)r≪min(d,k)。训练时 W0W_0W0​ 冻结，AAA 和 BBB 接收梯度。两条支路吃同一个输入，输出按坐标相加。原来的层是 h=W0xh=W_0xh=W0​x，现在变成

h=W0x+ΔWx=W0x+BAx.h=W_0x+\Delta Wx=W_0x+BAx. h=W0​x+ΔWx=W0​x+BAx.

可以用一个 2×22\times 22×2 的例子看这条约束在做什么。设

W0=[1001],x=[12],W_0=\begin{bmatrix}1&0\\0&1\end{bmatrix},\quad x=\begin{bmatrix}1\\2\end{bmatrix}, W0​=[10​01​],x=[12​],

那么 W0x=xW_0x=xW0​x=x。取 r=1r=1r=1，并设训练一段时间后

A=[10],B=[0.40].A=\begin{bmatrix}1&0\end{bmatrix},\quad B=\begin{bmatrix}0.4\\0\end{bmatrix}. A=[1​0​],B=[0.40​].

于是

BA=[0.4000],BAx=[0.40],h=[1.42].BA=\begin{bmatrix}0.4&0\\0&0\end{bmatrix},\quad BAx=\begin{bmatrix}0.4\\0\end{bmatrix},\quad h=\begin{bmatrix}1.4\\2\end{bmatrix}. BA=[0.40​00​],BAx=[0.40​],h=[1.42​].

AxAxAx 先把输入收成一个数，再乘上 BBB 的唯一一列。无论 xxx 怎么变，低秩支路加到输出上的向量都只能落在 BBB 的列空间里。r=1r=1r=1 时，这个列空间就是一条直线。

初始化也利用了这一点。AAA 用随机高斯初始化，BBB 用 0。训练开始时 BA=0BA=0BA=0，模型的输出就等于原来的预训练模型，低秩支路还没有改任何坐标。

作者随后把 ΔWx\Delta WxΔWx 再乘上 α/r\alpha/rα/r。α\alphaα 是一个不随输入变化的常数。在 Adam 中，如果初始化也按比例缩放，调 α\alphaα 和调学习率大致是同一件事，所以他们不再单独搜索 α\alphaα，而是把它设成第一次尝试的那个 rrr。这样在改变 rrr 时，更新的尺度不会只因为多了几条方向就需要整套学习率重调。实际前向因此是

h=W0x+αrBAx.h=W_0x+\frac{\alpha}{r}BAx. h=W0​x+rα​BAx.

例如 RoBERTa base 使用 r=8r=8r=8、α=8\alpha=8α=8，这个系数就是 1；GPT-2 使用 r=4r=4r=4、α=32\alpha=32α=32，系数就是 8。

如果把 LoRA 加到所有权重矩阵上，并且偏差也参加训练，那么把 rrr 提高到这些矩阵本身的秩时，表达能力就回到全量微调。Adapter 即使把瓶颈加大，额外模块仍然是一段带非线性的 MLP；prefix 即使增加特殊 token，仍然要占用序列长度。LoRA 变大时，收回来的是原来那个模型。

部署时可以先把低秩支路算进 W0W_0W0​，得到一个形状不变的矩阵，之后的推理就和普通微调模型一样，只做一次矩阵乘法。论文把合并写成 W=W0+BAW=W_0+BAW=W0​+BA。前向里还有系数 α/r\alpha/rα/r，所以加进 W0W_0W0​ 的应当是训练时真正使用的那一份更新；实现里通常把 α/r\alpha/rα/r 乘进 BBB，合并公式就和论文一致。换任务时，从 WWW 里减去当前更新，再加上另一对 B′A′B'A'B′A′。这一步只是矩阵加减，不改变推理时的网络深度。

Transformer

原则上，任何稠密层都可以加 LoRA。Transformer 的自注意力里有 Wq,Wk,Wv,WoW_q,W_k,W_v,W_oWq​,Wk​,Wv​,Wo​，MLP 里还有两块投影。作者把实验限制在注意力矩阵上，MLP 保持冻结。WqW_qWq​ 即使在实现里被切成多个注意力头，这里也把它看成一整块 dmodel×dmodeld_{\mathrm{model}}\times d_{\mathrm{model}}dmodel​×dmodel​。Fig. 1 里的方阵就是这种情形；一般公式仍允许 W0W_0W0​ 是 d×kd\times kd×k。

大多数实验只适配 WqW_qWq​ 和 WvW_vWv​。可训练参数量是

∣Θ∣=2×L^LoRA×dmodel×r.|\Theta|=2\times\hat L_{\mathrm{LoRA}}\times d_{\mathrm{model}}\times r. ∣Θ∣=2×L^LoRA​×dmodel​×r.

这里的 L^LoRA\hat L_{\mathrm{LoRA}}L^LoRA​ 是加了 LoRA 的权重矩阵个数，前面的 2 来自每块矩阵都有 AAA 和 BBB。GPT-3 有 96 层，只改 WqW_qWq​ 和 WvW_vWv​ 就是 192 块矩阵，dmodel=12288d_{\mathrm{model}}=12288dmodel​=12288。取 r=1r=1r=1 时，

∣Θ∣=2×192×12288×1=4718592,|\Theta|=2\times192\times12288\times1=4718592, ∣Θ∣=2×192×12288×1=4718592,

大约 4.7M，对应正文里 GPT-3 的较小设置。单独看一块 12288×1228812288\times1228812288×12288 的矩阵，全量更新约有 1.51×1081.51\times10^81.51×108 个参数；r=4r=4r=4 时 AAA 和 BBB 一共只有 2×12288×4=983042\times12288\times4=983042×12288×4=98304 个参数。

显存下降来自优化器状态。用 Adam 做全量微调时，冻结不住的每个参数都要留下梯度和动量类状态。LoRA 只给 AAA、BBB 保留这些状态。作者报告，GPT-3 175B 的训练显存从 1.2TB 降到 350GB。r=4r=4r=4 且只适配 query 和 value 时，任务检查点从 350GB 降到 35MB，大约是 10000 倍。保存 100 个任务时，大约是 350GB+35MB×100≈354GB350\mathrm{GB}+35\mathrm{MB}\times100\approx354\mathrm{GB}350GB+35MB×100≈354GB；若每个任务各存一份完整模型，则大约是 35TB。

同一设置下，全量微调的训练吞吐是每张 V100 32.5 tokens/s，LoRA 是 43.1 tokens/s，模型并行的切分方式相同。正文把这个差别概括为约 25% 的训练加速。按这两个吞吐计算，LoRA 相对全量微调大约高出 33%。

合并之后也有一个使用限制。若一个 batch 里的样本属于不同任务、因而使用不同的 AAA 和 BBB，就不能先把每一对 A,BA,BA,B 吸收进同一份 WWW。延迟不敏感时可以不合并，在前向里按样本选择对应的低秩支路。

实验

实验从 RoBERTa、DeBERTa 的自然语言理解，做到 GPT-2 的数据到文本生成，再放到 GPT-3 175B。理解任务使用 GLUE，生成任务使用 E2E NLG Challenge，大规模实验再加入 WikiSQL 和 SAMSum。GLUE 里 MNLI 报告 matched 与 mismatched 的总体准确率，CoLA 用 Matthews 相关，STS-B 用 Pearson 相关，其余任务用准确率，全部是越高越好。E2E 的 BLEU、NIST、METEOR、ROUGE-L 和 CIDEr 也是越高越好。训练硬件是 NVIDIA Tesla V100。优化器是 AdamW，学习率日程为线性衰减；各方法的学习率按方法和数据集调过，所以 GPT-3 上全量微调用 5×10−65\times10^{-6}5×10−6，LoRA 用 2×10−42\times10^{-4}2×10−4，这是两套分别调出来的步长。

基线

对照方法可以按“改哪些参数”分开看：

  • 全量微调 更新全部参数。GPT-2 上还有只更新最后两层的 FTTop2。
  • BitFit 只训练 bias，其余全部冻结。
  • Prefix-embedding 与 prefix-layer 就是上一节的两种输入侧适配。
  • Adapter 按插入位置区分。AdapterH 是 Houlsby 的每个 block 两处；AdapterL 是 Lin 等人只放在 MLP 之后的设计；AdapterP 接近 Pfeiffer 等人的设计；AdapterD 会丢掉一部分 adapter 层。
  • LoRA 在已有权重旁边平行加入 BABABA。除后面专门比较权重类型的实验外，只加在 WqW_qWq​ 和 WvW_vWv​ 上。

RoBERTa

RoBERTa base 约 125M，large 约 355M。LoRA 使用 rq=rv=8r_q=r_v=8rq​=rv​=8。base 的 α=8\alpha=8α=8，large 的 α=16\alpha=16α=16。作者报告 5 个随机种子的中位数，每个种子取最好的那个 epoch。

这里有一个会影响读表的训练细节。主实验沿用 RoBERTa 论文的做法，把 MRPC、RTE 和 STS-B 的 LoRA 从最好的 MNLI 检查点接着训，预训练权重仍然冻结。为了和 Houlsby、Pfeiffer 的 adapter 对齐，作者又做了一组受限实验：序列长度固定为 128，各任务使用相同 batch，而且 MRPC、RTE、STS-B 从原始预训练模型开始，不再借用 MNLI。这组结果标成 †\dagger†。

DeBERTa

DeBERTa XXL 有 1.5B 参数。LoRA 仍然取 rq=rv=8r_q=r_v=8rq​=rv​=8、α=8\alpha=8α=8，可训练参数 4.7M。MRPC、RTE、STS-B 同样从最好的 MNLI LoRA 检查点初始化。5 个种子取中位数。

全量微调的 GLUE 平均分是 91.1，LoRA 是 91.3。分任务看，MNLI 从 91.8 到 91.9±0.291.9\pm0.291.9±0.2，QNLI 两边都是 96.0，QQP 从 92.7 到 92.9±0.192.9\pm0.192.9±0.1，CoLA 从 72.0 到 72.4±1.172.4\pm1.172.4±1.1。SST-2 上 LoRA 是 96.9±0.296.9\pm0.296.9±0.2，略低于全量微调的 97.2。从 RoBERTa base 的约 125M 换到另一个家族的 DeBERTa XXL 1.5B 之后，低秩更新仍然能跟住全量微调的平均结果。

核心点和不足

LoRA 的核心是把下游适配写成冻结权重上的低秩增量。BABABA 与 W0W_0W0​ 平行，没有插入非线性层，所以训练结束后可以加回原矩阵；多个任务只需更换几十兆字节的 AAA 和 BBB。实验支持的是：在 GLUE、E2E、WikiSQL、MNLI 和 SAMSum 上，这样的增量可以达到或超过文中的全量微调，同时明显小于 adapter 在小 batch 下的额外延迟。第 48 层的分解则进一步说明，这些增量集中在少数不被预训练权重强调的方向上。

限制也同样具体：

  • 矩阵怎么选仍然是试出来的。 18M 预算下，WqW_qWq​ 配 WvW_vWv​ 最好，但 MLP、LayerNorm 和 bias 都没有做系统实验。
  • 小秩依赖预训练里已经有可放大的方向。 换一种预训练没见过的语言时，作者预期 r=dmodelr=d_{\mathrm{model}}r=dmodel​ 才会接近重训整个模型。GPT-2 medium 的 E2E 也说明，r=1r=1r=1 在 GPT-3 的两个数据集上够用，不能直接搬到所有模型和指标。
  • 合并与批内多任务不能同时要。 吸收进 WWW 之后，同一次前向难以让不同样本使用不同的 A,BA,BA,B。
  • 见过的生成类别不一定受益。 WebNLG 上，全量微调在见过类别的 BLEU 高于 LoRA。
  • 机制证据来自少量层和任务。 子空间热力图正文主要展示第 48 层，放大倍数也来自这一层的 WqW_qWq​。它解释了为什么这些任务上的小秩有效，还没有证明每一层、每一个任务的 ΔW\Delta WΔW 都只有同样的一两个方向。

总结

可以把 LoRA 收成三步：冻结 W0W_0W0​；用 B=0B=0B=0、AAA 为高斯的低秩支路学习 ΔW=αrBA\Delta W=\frac{\alpha}{r}BAΔW=rα​BA；部署时把这份更新加回 W0W_0W0​，推理深度与全量微调相同。

它之所以可能成功，是因为下游任务需要的权重变化集中在低维子空间里，而且这些方向在预训练矩阵中已经存在，只是不够强。下一步值得看的是 Aghajanyan 等人关于内在维度的测量，因为它提供了“预训练模型躺在低维子空间里”这一前提；也可以回到 Li 与 Liang 的 prefix-tuning，对照输入侧适配为什么会占用序列长度并在 token 增多时变差。论文自己留下的问题则是：选择 Wq,WvW_q,W_vWq​,Wv​ 之外，有没有更有根据的矩阵选择方法，以及 WWW 本身是不是也存在可利用的秩亏。
