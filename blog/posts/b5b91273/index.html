论文阅读：SpaCeFormer

发表于2026-11-25|更新于2026-11-25
|总字数:7.9k|阅读时长:31分钟|浏览量:—

引：SpaCeFormer 由 NVIDIA 的 Chris Choy、Jan Kautz 与 POSTECH 团队（Junha Lee、Chunghyun Park、Minsu Cho）合作提出，瞄准的是开放词汇三维实例分割里最现实的矛盾：精度高的多阶段 2D+3D 管线慢到每场景几百秒，而现有端到端伪标签方法又受限于碎片化掩码和外部候选框。作者一方面用多视角掩码聚类与多视角 VLM 描述构建了 300 万条标注的 SpaCeFormer-3M 数据集（掩码召回率从 2.5% 提升到 54.3%），另一方面设计了结合空间窗口与 Morton 曲线的 Space-Curve Attention 及 RoPE 增强的无候选框解码器，仅输入三维点云、单次前向即可在 0.12–0.30 秒 内完成整场景实例分割。

图来自原论文 Figure 1：Replica 零样本评测上的精度（mAP）与单场景延迟（对数坐标）。SpaCeFormer（红色五角星）在不使用真实 3D 标注监督的开放词汇方法中达到 Pareto 最优（24.1 mAP，0.22 s），也是唯一进入亚秒级交互区间（<1 s<1\text{ s}<1 s）的方法。

背景

想让机器人或 AR/VR 设备在真实三维环境里按自然语言指令找东西，模型就不能只认训练集里那几十个固定类别，而必须具备开放词汇三维实例分割（Open-Vocabulary 3D Instance Segmentation）能力：给定一帧三维点云和任意文本描述，把场景里对应的每个物体实例精确分割出来。

但由于大规模“三维实例掩码–文本”配对数据极度稀缺，过去的工作主要沿着两条路线绕行，各自撞上了不同的墙：

  • 多阶段 2D+3D 推理管线：如 OpenMask3D (Takmaz et al., 2023)、Open3DIS (Nguyen et al., 2024)、SAI3D (Yin et al., 2024)、Open-YOLO 3D (Boudjoghra et al., 2025) 和 OpenTrack3D (Zhou et al., 2025)。它们先用 Mask3D (Schult et al., 2023) 或 SAM / YOLO-World 在三维或二维视角上生成候选掩码，再逐帧投影提取 CLIP 特征并做跨视角融合。这种做法不仅在各阶段间累积误差、依赖数据集相关的启发式阈值，更致命的是逐帧跑 2D 基础模型导致推理极慢——每场景动辄几十到数百秒，完全无法用于交互式场景。
  • 基于伪标签的端到端训练：如 RegionPLC (Yang et al., 2024b) 和 Mosaic3D (Lee et al., 2025a)，试图用 2D 基础模型自动生成三维伪标签来直接训练 3D 网络。但它们普遍采用“单视角 2D 掩码反投影到 3D + 单视角生成描述”的做法：遮挡让同一个物体被拆成很多碎片化掩码，不同视角看到的局部外观又让描述彼此打架。此外，现有的高效 3D 主干（如 Point Transformer v3 (Wu et al., 2024) 和 OctFormer）依赖空间填充曲线把点云拉成一维序列再切块做注意力，这会把三维空间中紧挨着的点打散到不同窗口里，难以保住实例边界所需的局部几何连贯性。

基于这两个痛点，作者的思路很直接：如果要让一个无候选框（proposal-free）的三维模型仅凭点云单次前向就学会切出完整物体，数据上必须先有完整且视角一致的三维实例监督，架构上必须同时保住局部几何边界与全局注意力的多样性。由此，本文的主要贡献可以概括为四点：

  1. 构建 SpaCeFormer-3M 数据集：覆盖 7,361 个室内场景、604,127 个三维实例掩码与 302 万条多视角一致的文本描述，掩码召回率（IoU >0.5>0.5>0.5）达到 54.3%，是此前单视角伪标签管线（2.5%）的 21 倍以上。
  2. 提出 Space-Curve Attention 主干：将固定几何尺度的三维空间窗口注意力与固定 token 长度的 Morton 曲线序列化注意力结合，在保持高效的同时将窗口内平均点对距离降低 28.6%。
  3. 设计 RoPE 增强的无候选框解码器：通过可学习 query 与引入绝对三维坐标的 3D RoPE 交叉注意力，直接从点特征预测实例掩码与 CLIP 嵌入，彻底摆脱外部候选框网络和后处理聚类。
  4. 在 Replica（24.1 mAP，0.22 s）、ScanNet++（22.9 mAP，0.30 s）和 ScanNet200（同口径下 11.1 mAP，0.12 s）上取得大幅领先的速度–精度权衡。

数据集生成：SpaCeFormer-3M

训练一个直接预测完整实例掩码的模型，最怕的就是训练标签本身支离破碎。作者从四个大规模室内 RGB-D 数据集收集原始场景：ScanNet (Dai et al., 2017)、ScanNet++ (Yeshwanth et al., 2023)、Matterport3D (Chang et al., 2018) 和 ARKitScenes (Baruch et al., 2021)，覆盖专业高精扫描与普通手机采集，统一相机内参和位姿后，通过三步流水线自动生成高质量的“3D 掩码–文本”配对数据。

图来自原论文 Figure 2：SpaCeFormer-3M 的三步生成流程，包括基于几何重叠的视角采样、基于 MaskClustering 的免训练 3D 掩码聚合，以及基于 k-medoids 选帧的多视角 VLM 描述生成。

  1. 高效视角采样：原始视频流相邻帧高度冗余。作者顺序遍历帧序列，只有当当前帧反投影点云与上一入选帧点云的几何重叠度 ⋂(Pti,Ptj)\bigcap(\mathcal{P}_{t_i}, \mathcal{P}_{t_j})⋂(Pti​​,Ptj​​)（即当前帧中能在参考帧距离阈值内找到最近邻的点数比例）低于阈值时才保留该帧，从而用最少视角覆盖完整场景。
  2. 免训练三维掩码聚合：先用 SAM2 (Ravi et al., 2024) 在采样帧上提取 2D 掩码并反投影到 3D，再用 MaskClustering (Yan et al., 2024) 根据空间邻近度、可见性与包含关系将多视角碎片聚合成完整 3D 实例。通过严格过滤（visibility>0.3\text{visibility} > 0.3visibility>0.3 且 consensus>0.9\text{consensus} > 0.9consensus>0.9），筛掉残缺碎片。这一步同时留下了一个关键副产物：每个聚合后的 3D 实例到其所有关联 2D 视角的“一对多”映射。
  3. 多视角一致描述：为了避免 VLM 只盯着单个视角胡乱发挥，作者利用上一步的映射关系找回该实例出现的所有帧，按掩码可见性加权对帧时间戳做 k-medoids 聚类，选出最多 KKK 个代表视角，并同时以带空间上下文的裁剪图和去背景掩码图两种形式喂给 VLM。提示词要求模型总结形状、纹理、材质等固有属性以及稳定的空间关系；通过更换采样种子，每个 3D 实例生成 5 条多样化描述（平均长度 15.5 个词）。

最终得到的 SpaCeFormer-3M 包含 7,361 个场景、604,127 个 3D 实例掩码和 3,020,635 条描述。在 312 个 ScanNet 训练场景上与真实标注对比，单视角提升的 Mosaic3D 平均每场景只产出 16.1 个掩码，IoU >0.5>0.5>0.5 的召回率仅 2.5%；而 SpaCeFormer-3M 平均每场景产出 65.2 个掩码，精确率 33.6%、召回率 54.3%。这种几何完整性正是后续无候选框解码器能够学出清晰物体边界的前提。

方法：SpaCeFormer

SpaCeFormer 接收带特征的三维点云 P={(pi,fi)}i=1M\mathcal{P}=\{(p_i, f_i)\}_{i=1}^MP={(pi​,fi​)}i=1M​ 作为输入，输出场景中每个预测实例的逐点软掩码 M\mathbf{M}M、前景概率 C\mathbf{C}C 以及对应的开放词汇特征 Z\mathbf{Z}Z。整套网络由空间–曲线主干网络（Space-Curve Backbone）和RoPE 增强的无候选框解码器（Proposal-Free Decoder）组成，数据流如下：

flowchart TD
    IN["输入点云 P = {(p_i, f_i)}"] --> VOX["体素化与平均池化 → 稀疏体素特征 X"]
    VOX --> ENC["U-Net 编码器（SparseConv3d + Space-Curve Attention + 3D RoPE）"]
    ENC -->|跳跃连接 + 上采样| DEC["U-Net 解码器 → 体素特征 D^1"]
    DEC -->|近邻插值映射回点空间| PFEAT["逐点特征 F 与 CLIP 对齐特征 Z_vox"]
    PFEAT -->|前向随机采样 S 个点| KEY["Key/Value（对 Key 施加绝对坐标 3D RoPE）"]
    QINIT["可学习 Query Q^(0)（不施加 RoPE）"] --> CROSS["Cross-Attention（带掩码注意力）"]
    KEY --> CROSS
    CROSS --> SELF["Self-Attention + FFN（重复 T=3 轮共享权重精炼）"]
    SELF -->|t < T| CROSS
    SELF -->|t = T, 结合全量点特征 F| HEADS["三路预测头：掩码 M / 前景 C / CLIP 特征 Z"]

主干网络先在稀疏体素网格上通过多尺度 U-Net 提取兼具局部几何边界与全局上下文的特征，再插值回原始点云；解码器则像 DETR (Carion et al., 2020) 和 Mask2Former (Cheng et al., 2022) 那样，让一组可学习 query 在点特征上做掩码注意力精炼，直接吐出所有实例的掩码和语义嵌入。下面按模块拆解其中的关键设计。

预备记号与两种窗口的区分

设输入点云为 P={(pi,fi)}i=1M\mathcal{P}=\{(p_i, f_i)\}_{i=1}^MP={(pi​,fi​)}i=1M​，其中 pi∈R3p_i\in\mathbb{R}^3pi​∈R3 是三维坐标，fi∈Rdinf_i\in\mathbb{R}^{d_{in}}fi​∈Rdin​ 是颜色等附加特征。为兼顾效率，主干网络将三维空间离散化为稀疏体素网格 V={v1,…,vN}\mathcal{V}=\{v_1,\ldots,v_N\}V={v1​,…,vN​}，对每个非空体素 viv_ivi​ 内的点特征做平均池化，得到输入张量 X∈RN×din\mathbf{X}\in\mathbb{R}^{N\times d_{in}}X∈RN×din​。

在进入注意力机制前，必须先分清两个容易混淆的概念：

  • 空间窗口大小（Spatial window size）：体素坐标系下的固定三维几何尺寸（例如 H×W×DH\times W\times DH×W×D 个体素组成的立方体）。由于三维点云高度稀疏，每个立方体内实际包含的非空体素数量各不相同（从 1 到 H×W×DH\times W\times DH×W×D 不等）。
  • 注意力窗口大小（Attention window size）：单次自注意力计算中实际参与交互的 token 数量（序列长度 LLL）。

把这两个概念拆开后，Space-Curve Attention 的两种互补机制就一目了然了：

  • 空间窗口注意力（Spatial Window Attention）：按固定几何尺寸划分三维立方体窗口，注意力窗口大小可变。它严格保住了局部几何邻域，绝不会把相邻体素拆散。
  • 曲线注意力（Curve / Morton Code Attention）：用 Morton 空间填充曲线（Z 阶曲线，将 (x,y,z)(x,y,z)(x,y,z) 的二进制坐标位交替拼接成一维编码）把体素重排为序列 π:{1,…,N}→{1,…,N}\pi:\{1,\ldots,N\}\rightarrow\{1,\ldots,N\}π:{1,…,N}→{1,…,N}，再切成固定 token 长度 LLL 的连续片段 (Wu et al., 2024)。它的注意力窗口大小固定，但空间跨度可变，能为网络引入跨区域的随机性与结构多样性。

两种机制都在各自窗口内做双向多头自注意力，把复杂度从 O(N2)O(N^2)O(N2) 降到 O(N⋅Lmax⁡)O(N\cdot L_{\max})O(N⋅Lmax​)。

这里 LN\text{LN}LN 表示层归一化，MHSA\text{MHSA}MHSA 正是作用在上一节定义的空间窗口或 Morton 曲线片段上。多尺度编码器通过步长卷积（strided convolution）逐步下采样并缓存跳跃连接，对称的解码器则逐步上采样融合跳跃连接。为防止模型死记某一种网格划分或序列化顺序，每次前向传播都会随机置换序列化策略，并对空间窗口沿 (x,y,z)(x,y,z)(x,y,z) 轴的任意组合随机移位半个窗口大小（W/2W/2W/2）。最终解码器输出的体素特征 D1\mathbf{D}^1D1 通过近邻插值映射回原始点云，得到逐点特征 F∈RM×D\mathbf{F}\in\mathbb{R}^{M\times D}F∈RM×D 供实例解码器使用，同时分支出一个轻量投影头映射到 CLIP 对齐空间。

Space-Curve 注意力与 3D RoPE

为什么不能像 Point Transformer v3 那样只用 Morton 曲线？虽然 Morton 码在语义分割上很强，但因为它是按一维索引等长切分（固定 token 数 LLL），遇到点云密度变化或跨越象限边界时，三维空间里紧贴在一起的体素经常被硬生生切进两个不同的注意力段里，而同一段里反而可能塞进相距很远的点。对于需要精确勾勒物体边缘的实例分割来说，这种局部空间连贯性的破坏是致命的。

图来自原论文 Figure 5：左图为 Morton 序列化后的窗口划分（路径跳跃且跨度大），右图为非重叠空间窗口划分（严格保持局部几何邻接）。

作者定义了一个直观的指标来衡量窗口内的空间连贯性：计算同一注意力窗口内所有体素对的平均欧氏距离。定量对比显示，空间窗口注意力将窗口内平均点对距离降低了 28.6%。而在具体调度上，SpaCeFormer 只在最高分辨率的两个层级（窗口大小分别为 64 和 48）启用空间窗口注意力来保住精细边界，在更粗的层级继续使用 Morton 曲线注意力提供全局视角。

图来自原论文 Figure 6：左图为 Morton 编码下的均匀块对角注意力掩码；中图为空间窗口直接索引产生的稀疏不规则掩码；右图为按所属窗口索引重排后的 Sorted Window 掩码，既严格保留了空间邻近性，又恢复了可高效并行计算的变长块对角结构。

直接按空间坐标划分窗口时，同一窗口里的体素在一维内存里并不连续（如 Figure 6 中图所示）。为此，作者在实现时按“窗口索引”对体素重排，得到 Sorted Window 掩码（Figure 6 右图），重新恢复了规整的块对角结构，从而能直接调用高效的变长注意力算子。

为了在窗口内直接编码三维相对几何关系，SpaCeFormer 在计算注意力点积时对 Query 和 Key 施加 3D 旋转位置编码（3D RoPE） (Su et al., 2024)。对于位于三维坐标 pi=(xi,yi,zi)\mathbf{p}_i=(x_i,y_i,z_i)pi​=(xi​,yi​,zi​) 和 pj=(xj,yj,zj)\mathbf{p}_j=(x_j,y_j,z_j)pj​=(xj​,yj​,zj​) 的两个体素，注意力内积写为：

⟨qi,kj⟩=qiRΘ,pj−pikj⊤(4)\langle\mathbf{q}_{i},\mathbf{k}_{j}\rangle=\mathbf{q}_{i}\mathbf{R}_{\Theta,\mathbf{p}_{j}-\mathbf{p}_{i}}\mathbf{k}_{j}^{\top} \tag{4} ⟨qi​,kj​⟩=qi​RΘ,pj​−pi​​kj⊤​(4)

RΘ,Δp=[Rx(θx)Ry(θy)Rz(θz)](5)\mathbf{R}_{\Theta,\Delta\mathbf{p}}=\begin{bmatrix}\mathbf{R}_{x}(\theta_{x})&&\\ &\mathbf{R}_{y}(\theta_{y})&\\ &&\mathbf{R}_{z}(\theta_{z})\end{bmatrix} \tag{5} RΘ,Δp​=​Rx​(θx​)​Ry​(θy​)​Rz​(θz​)​​(5)

  • qi,kj\mathbf{q}_i, \mathbf{k}_jqi​,kj​：分别表示体素 iii 的 query 向量与体素 jjj 的 key 向量；
  • Rd(θd)\mathbf{R}_d(\theta_d)Rd​(θd​)（d∈{x,y,z}d\in\{x,y,z\}d∈{x,y,z}）：沿特征通道两两配对施用的二维旋转矩阵，三个空间轴彼此独立分配不同的特征维度子空间；

通过把相对坐标差直接折算成正交旋转角，模型不需要额外学习位置偏置表就能感知体素间的精确三维距离与方向；在主干网络中，RoPE 编码的是局部滑动窗口内的相对位移 pj−pi\mathbf{p}_j-\mathbf{p}_ipj​−pi​。

Proposal-Free 实例分割解码器

拿到主干输出的逐点特征 F∈RN×D\mathbf{F}\in\mathbb{R}^{N\times D}F∈RN×D（此处记点云点数为 NNN）后，传统多阶段方法会先跑一个 Mask3D 或 Segment3D 生成候选框再做特征池化与合并；SpaCeFormer 则完全省掉外部候选框网络，直接用一组可学习 query 在单次前向中完成预测。

图来自原论文 Figure 8：解码器在点空间中运行。每次前向从场景点中随机采样 SSS 个点并对其 Key 施加 3D RoPE，引导 QQQ 个可学习 query 经过 TTT 轮共享权重的 Cross-Attention、Self-Attention 与 FFN 迭代精炼，最后结合全量点特征预测 CLIP 特征 Z\mathbf{Z}Z 与实例掩码 M\mathbf{M}M。

具体来说，解码器初始化 Q=200Q=200Q=200 个可学习 query 嵌入 Q(0)∈RQ×D\mathbf{Q}^{(0)}\in\mathbb{R}^{Q\times D}Q(0)∈RQ×D，并在 T=3T=3T=3 轮共享参数的迭代中交替执行交叉注意力、自注意力与 FFN。为了控制大场景下的显存与计算开销，每次前向传播仅随机采样 SSS 个场景点作为交叉注意力的 Key 和 Value。

这里有一个很关键的设计细节：在交叉注意力中，作者只对场景点的 Key 施加 3D RoPE（R(Fs,Ps)\mathcal{R}(\mathbf{F}_s, \mathbf{P}_s)R(Fs​,Ps​)），而可学习 query 本身不经过 RoPE。因为可学习 query 并不固定绑定某个物理坐标，让 Key 带着旋转编码就等于把场景点的绝对三维坐标注入了注意力计算，使不同的 query 能够自然区分空间位置不同的同类物体（比如房间左侧的椅子和右侧的椅子）。（注：论文附录 A.3 也给出过若为 query 分配坐标时对双方同步施加 RoPE 的扩展形式，但主实验采用的正是仅旋转 Key 的轻量版本。）

经过 TTT 轮精炼后，解码器丢弃采样限制，用全部 NNN 个点的特征通过三路预测头输出结果：

  • 实例掩码：M=σ(F(WMQ(T))⊤)∈RN×Q\mathbf{M}=\sigma(\mathbf{F}(\mathbf{W}_M\mathbf{Q}^{(T)})^\top)\in\mathbb{R}^{N\times Q}M=σ(F(WM​Q(T))⊤)∈RN×Q，每一列给出场景所有点属于该实例的软概率；
  • 前景得分：C=WCQ(T)∈RQ×2\mathbf{C}=\mathbf{W}_C\mathbf{Q}^{(T)}\in\mathbb{R}^{Q\times 2}C=WC​Q(T)∈RQ×2，判断该 query 是否命中真实前景物体；
  • CLIP 嵌入：Z=WCLIPQ(T)∈RQ×DCLIP\mathbf{Z}=\mathbf{W}_{\text{CLIP}}\mathbf{Q}^{(T)}\in\mathbb{R}^{Q\times D_{\text{CLIP}}}Z=WCLIP​Q(T)∈RQ×DCLIP​，直接预测实例的语言对齐特征（而非在掩码上做特征池化）。推理时只需计算 Z\mathbf{Z}Z 与所有候选类别文本嵌入的余弦相似度，取 argmax 即完成开放词汇分类。

训练阶段通过匈牙利二分匹配（Hungarian matching）将预测 query 与 SpaCeFormer-3M 的 3D 伪标签对齐，复合损失函数为：

L=λmaskLmask+λCLIPLCLIP+λfgLfg\mathcal{L}=\lambda_{\text{mask}}\mathcal{L}_{\text{mask}}+\lambda_{\text{CLIP}}\mathcal{L}_{\text{CLIP}}+\lambda_{\text{fg}}\mathcal{L}_{\text{fg}} L=λmask​Lmask​+λCLIP​LCLIP​+λfg​Lfg​

  • Lmask\mathcal{L}_{\text{mask}}Lmask​：由 Sigmoid 二元交叉熵（BCE）与 Dice 损失组成，监督逐点掩码边界；
  • LCLIP\mathcal{L}_{\text{CLIP}}LCLIP​：InfoNCE 对比损失 (Oord et al., 2018)，拉近匹配 query 的 Zq\mathbf{Z}_qZq​ 与目标文本 CLIP 嵌入；
  • Lfg\mathcal{L}_{\text{fg}}Lfg​：二分类交叉熵损失，监督 query 是否为有效前景实例。

值得一提的是，作者在优化器上没有全盘用 AdamW，而是对所有二维及以上的矩阵隐藏层参数采用 Muon 优化器 (Jordan et al., 2024)（先算 SGD-Nesterov 动量更新，再通过 5 步五次 Newton–Schulz 迭代将更新矩阵近似正交化），其余非矩阵参数使用 AdamW。

实验

作者在 SpaCeFormer-3M 上训练模型（4 节点 ×\times× 8 张 H100，batch size 32，训练 25k 步约 1.5 天），并在 Replica（8 场景，完全零样本）、ScanNet++（100 类）和 ScanNet200（200 类）三个基准上测试。在单张 NVIDIA GB200（FP16 autocast，batch size 1）上，端到端推理耗时分别为 ScanNet200 0.12 s（约 170k 点）、Replica 0.22 s（约 800k 点）、ScanNet++ 0.30 s（约 1.6M 点），已不含可跨场景复用的单次 CLIP 文本编码（约 0.02 s）。

从结果可以看出三点直接支撑前文设计的结论：

  1. 跨数据集零样本泛化极强：Replica 从未出现在训练集中，SpaCeFormer 仅靠 3D 点云就拿到 24.1 mAP，在所有不使用 GT 3D 标注的方法中处于 Pareto 最优，比 Open-YOLO 3D 快约 75 倍、比 OpenMask3D 快约 2,488 倍；在精细重建的 ScanNet++（100 类）上达到 22.9 mAP，直接反超了需要多视角 2D RGB-D 输入的 OpenTrack3D（20.6 mAP），速度提升超过 1,000 倍。
  2. 彻底验证“去掉 GT 候选框”的难点：在 200 类的 ScanNet200 上，一旦现有方法把基于 GT 训练的 Mask3D 换成开放词汇的 Segment3D 候选框，精度就会雪崩（Mosaic3D 从 11.8 mAP 掉到 2.7 mAP）。而在“仅 3D 输入 + 无 GT + 无候选框”的同口径下，SpaCeFormer 达到 11.1 mAP，是 Mosaic3D w/ Decoder（3.9 mAP）的 2.8 倍；如果给它接上 Mask3D 候选框，也能进一步升到 16.7 mAP。
  3. 类无关掩码边界紧致：在不考虑语义标签的 ScanNet200 类无关实例分割评测中，SpaCeFormer 拿到 22.5 AP、45.7 AP50 和 64.4 AP25，AP25 与 AP50 均超过所有纯 2D 或 3D+2D 开放词汇基线，说明无候选框解码器配合空间窗口确实能切出紧贴物体边界的掩码。

消融实验

作者在 ScanNet200 验证集上逐一拆解了核心模块的作用：

  • Space-Curve 注意力组合：单独使用 Morton 曲线（PTv3 基线）为 9.47 mAP（类无关 23.31 AP），单独使用空间窗口为 9.52 mAP（类无关 25.47 AP），而将两者结合（最高两层用 64/48 空间窗口、粗层用 Morton 曲线）在 200 类语义实例分割上跃升至 11.09 mAP（mAP50 从 16.41%/16.82% 提升至 18.78%）。局部边界保真与全局上下文多样性缺一不可。
  • 解码器中的 3D RoPE：对比无位置编码（5.97 mAP）、绝对位置编码 APE（5.95 mAP）和可学习相对位置偏置（6.46 mAP），3D RoPE 达到 7.60 mAP（在相同 25k 步消融配置下），证明把绝对坐标通过旋转矩阵注入交叉注意力能有效区分不同位置上的同类物体。
  • Query 初始化策略：对比可学习 query（DETR 风格）、最远点采样（FPS）与随机初始化，可学习 query 在类无关掩码质量上达到 19.82 AP，明显高于 FPS（17.97 AP）和随机初始化（14.64 AP）。

核心价值与不足

把整篇论文串起来看，SpaCeFormer 最值得关注的价值在于打通了“高质量多视角伪标签”与“无候选框 3D 单阶段架构”之间的正反馈：过去端到端 3D 开放词汇方法做不好，往往不是解码器本身不行，而是单视角伪标签太碎导致学不出完整物体，且序列化主干把局部边界打散了；SpaCeFormer 同时把这两块短板补齐，证明了只靠 3D 点云单次前向也能做到亚秒级且逼近甚至反超 2D+3D 管线的分割质量。

同时，论文也坦诚指出了当前的几项限制：

  • ScanNet200 长尾细粒度上仍有差距：在 200 类复杂室内场景中，SpaCeFormer（11.1 mAP）与使用 2D+3D 多视角流（如 OpenTrack3D 26.0 mAP）或 GT 训练候选框（如 Open-YOLO 3D 24.7 mAP）的方法仍有明显差距，纯点云对小物体与精细纹理的分辨力依然受限。
  • 固定 query 数量的容量上限：解码器固定使用 Q=200Q=200Q=200 个可学习 query，当单个场景包含大量小物体时，query 槽位可能不足。
  • 场景域局限：目前的训练与评测全部集中在室内 RGB-D 重建场景，向稀疏点云、室外自动驾驶或开放野外环境的迁移尚未验证。

总结

SpaCeFormer 围绕“去掉慢速多阶段 2D+3D 管线、实现实时级开放词汇三维实例分割”这一目标，完成了一套紧凑的闭环设计：

  1. 数据侧：用几何重叠去冗余 + MaskClustering 多视角聚类 + 多视角 VLM 描述构建 SpaCeFormer-3M，先解决训练掩码破碎与文本不一致的源头问题；
  2. 主干侧：用 Space-Curve Attention（细粒度层空间窗口 + 粗粒度层 Morton 曲线）与局部 3D RoPE 兼顾物体边缘的几何连贯性与计算效率；
  3. 解码侧：用固定可学习 query 与绝对坐标 3D RoPE 交叉注意力单次前向直接输出掩码与 CLIP 特征，把单场景推理压到 0.12–0.30 秒。

如果后续继续跟进这一方向，值得关注两个问题：一是如何在保持亚秒级延迟的前提下，让固定数量的 query 自适应密集小物体场景；二是能否把这种“多视角一致伪标签 + 空间窗口主干”的范式迁移到室外 LiDAR 或动态四维场景中。
