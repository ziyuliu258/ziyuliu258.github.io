论文阅读：LeRF

发表于2026-11-21|更新于2026-11-22
|总字数:4.1k|阅读时长:13分钟|浏览量:—

引：本文由 UIUC、上海交大、UC Merced 与 Amazon AGI 的研究者完成。它要解决的是 VLM 的视角采择 (perspective taking)：问题是“从那个人的角度看，谁在他左边”，模型却总按相机视角回答。LeRF 让模型自己预测一个贴在被指对象身上的参考坐标系，再把它画回原图，把“心里转视角”变成“看图上的箭头”。

图来自原论文 Figure 1：左侧区分自我中心、他人中心与假想视角；右侧显示显式参考系能把“工人左边有几个人”答对。

背景

视角采择要求模型从相机之外的某个视点解释空间关系。论文区分三种情形：以相机为基准的 egocentric、以场景中某个实体为基准的 allocentric，以及以“想象自己坐在沙发上”这类虚拟观察者为基准的 hypothetical。三者共用同一个场景，只是参考系不同。

VLM 在这里有一种稳定的失败模式：它会把问题悄悄替换成相机视角下的问题。问“戴橙色手套的工人左边还有几个人”，Qwen3.5-9B 数的是画面左侧的两个人，答 2；正确答案是 0，因为那两个人都在他的前方偏右。这类错误不是算错，而是根本没换参考系。

已有的补救办法各走一端。SpatialReasoner 让模型显式估计三维点坐标再做几何计算，代价是把整个流程压在了三维感知的准确性上，坐标一错，后面全错。APC 用多个外部视觉模型重建粗糙三维场景，再变换到目标视点，问题则是多阶段流水线带来的推理开销，以及“总是要变换”的刚性假设——很多问题其实不需要换视角。

作者先做了一个很朴素的实验：用 OrientAnything-V2 估计参考实体的朝向，把对应的坐标轴画到图上，再让同一个模型回答。仅仅这一步，准确率就明显上升。这提示了一件事：视角变换难，可能难在它没有被外化成可见的东西。于是问题变成：能不能让 VLM 自己学会建立这个参考系，并在它上面推理？

方法

整体流程是一个人机都看得懂的闭环：判断要不要建系 → 定位参考实体 → 预测坐标系在图像上的投影 → 用确定性渲染器画回原图 → 基于渲染结果回答。训练上分监督微调和强化学习两段。

图来自原论文 Figure 2：上半部分是两轮推理（决定调用、渲染、再作答），下半部分是 SFT 与 GRPO 两个训练阶段。

参考系表示

给定图像 III 和空间问题 qqq，模型先找出问题指定或暗示的参考实体，再预测附着在它身上的坐标系。坐标轴的定义是：+X+X+X 为实体自身的前方，+Y+Y+Y 为左方，+Z+Z+Z 为上方。

关键选择是： 它不预测三维坐标，只预测坐标系在二维图像上的投影。

F^={o^, p^front, p^left, p^up},o^,p^front,p^left,p^up∈R2,\hat{F}=\{\hat{o},\ \hat{p}_{\text{front}},\ \hat{p}_{\text{left}},\ \hat{p}_{\text{up}}\},\qquad \hat{o},\hat{p}_{\text{front}},\hat{p}_{\text{left}},\hat{p}_{\text{up}}\in\mathbb{R}^{2}, F^={o^, p^​front​, p^​left​, p^​up​},o^,p^​front​,p^​left​,p^​up​∈R2,

其中 o^\hat{o}o^ 是投影后的原点，p^⋅\hat{p}_{\cdot}p^​⋅​ 是三条轴投影后的端点。为了和 Qwen3.5 的预训练表示对齐，每个点用 [0,1000]2[0,1000]^{2}[0,1000]2 的整数坐标表示，原点在图像左上角。

作者给了两个理由。第一，绝大多数视角采择问题问的是“左/右/前/后”这类方向关系，不需要米制距离，二维投影已经够用。第二，从单张图恢复准确的三维坐标本身就很难，估出来的误差会一路传到推理；二维表示则绕开了这个误差源。

这里有个细节值得说明：当某条轴几乎垂直于图像平面时，它的投影会缩成一个很短的线段，方向信息在图上几乎消失。作者用几何符号补上： ⊙ 表示轴指向相机、穿出画面，⊗ 表示轴背离相机、穿入画面。这样即使投影退化，朝向信息也没有丢。

得到 F^\hat{F}F^ 之后，调用一个轻量的确定性渲染函数把它画到原图上：

I~=R(I,F^).\tilde{I}=\mathcal{R}\left(I,\hat{F}\right). I~=R(I,F^).

也就是说，渲染这一步不引入任何学习参数，模型要学的只是预测那几个点。

两阶段推理

给定图像和问题，模型先输出一个中间动作：

a1∼πθ(⋅∣q,I),a1∈{NoCall, Call(e^,F^)},a_1\sim\pi_\theta(\cdot\mid q,I),\qquad a_1\in\left\{\text{NoCall},\ \text{Call}\left(\hat{e},\hat{F}\right)\right\}, a1​∼πθ​(⋅∣q,I),a1​∈{NoCall, Call(e^,F^)},

e^\hat{e}e^ 是参考实体，F^\hat{F}F^ 是它的参考系，NoCall\text{NoCall}NoCall 表示这个问题不需要换视角。工具返回的视觉结果是

v1={R(I,F^),a1=Call(e^,F^),∅,a1=NoCall.v_1= \begin{cases} \mathcal{R}\left(I,\hat{F}\right), & a_1=\text{Call}\left(\hat{e},\hat{F}\right),\\ \varnothing, & a_1=\text{NoCall}. \end{cases} v1​={R(I,F^),∅,​a1​=Call(e^,F^),a1​=NoCall.​

第二阶段之前，作者做了一件很关键的事： 把第一轮动作里的数值参数删掉，只留渲染后的图，记作 aˉ1\bar{a}_1aˉ1​。然后

y∼πθ(⋅∣q,I,aˉ1,v1).y\sim\pi_\theta\left(\cdot\mid q,I,\bar{a}_1,v_1\right). y∼πθ​(⋅∣q,I,aˉ1​,v1​).

也就是说，模型知道自己“调用过工具、参考的是谁”，但拿不到那八个数字，只能去看图上的三根轴。这个约束把“读数字算一算”这条捷径堵死了，逼着模型真的使用渲染出来的方向线索。反过来，如果保留数值，渲染就退化成一种装饰。

NoCall\text{NoCall}NoCall 分支同样重要。模型要学会判断问题是否需要换视角：相机视角下的左右、图上的位置、数量统计，这些都不需要建系；无差别调用工具只会平白引入一次图像变换和额外计算。训练数据里约 20% 是这类“不调用”的样本，模型在这些样本上输出一个特殊标记 NO_TOOL_CALL。

训练

第一阶段是监督微调。 作者把参考实体、原点、三条轴端点组织成结构化的 tool call 作为训练目标，用标准的自回归交叉熵优化，视觉编码器和多模态投影层保持冻结，只训 LLM 主干 (LoRA, rank 8)。这一步教的是两件事：定位参考实体，以及把它的朝向投影成三条轴。

第二阶段是强化学习。 在 SFT 的能力之上用 GRPO 继续训练视角采择问答，奖励只看最终答案对错：对 1 分，错 0 分，中间预测和工具调用都不额外给分。

这里有一个我认为是全篇最细的设计： 参考系预测的那些 token 不参与策略梯度，优势加权的损失只作用在其后的推理与答案 token 上。原因是 RL 的奖励信号只关心答案，如果让梯度也流回坐标预测，模型可能为了拿分而把坐标系改得“更好答”，从而破坏 SFT 学到的朝向能力。把两者隔开，相当于把“看”和“想”分成两件事分别训练。

训练数据

SFT 阶段的参考系标注来自带位姿的物体与人体数据集：ImageNet3D、Omni6DPose-SOPE 和 BEDLAM。每个数据集有自己的规范坐标系，作者把它们逐一映射到“前、左、上”，其中 Omni6DPose-SOPE 用人工指定的类别级映射，并剔除没有明确朝向的类别——这一点很实际，一个球或一盆植物本来就没有“前方”。

给定实体在相机坐标系下的位姿 (R,t)(R,t)(R,t) 与内参 KKK，投影后的原点与轴端点为

o=πK(t),pd=o+s JπK(t) R ed,o=\pi_K(t),\qquad p_d=o+s\,J_{\pi_K}(t)\,R\,e_d, o=πK​(t),pd​=o+sJπK​​(t)Red​,

其中 πK\pi_KπK​ 是针孔投影，JπKJ_{\pi_K}JπK​​ 是它的雅可比，ede_ded​ 是 d∈{front,left,up}d\in\{\text{front},\text{left},\text{up}\}d∈{front,left,up} 对应的规范单位轴，sss 是一个共享尺度，用来保持三条轴投影长度的相对比例。

这个式子值得停一下。轴是三维空间里的方向，投影到图像上之后，它的方向由投影在该点的雅可比决定，也就是一阶近似：从原点出发，沿这个方向走一小步，落到图像上的位移方向。三条轴共用同一个 sss，所以它们的相对长度还能反映三维方向与图像平面的夹角——正对相机的轴会被压短，这也正是前面要用 ⊙/⊗ 补信息的原因。

RL 阶段的数据来自两个公开的视角采择 VQA 集合：MultihopSpatial-train（6.79K 条，1 到 3 跳推理）与 SpatialReasoner-RL（1.2K 条）。

实验

作者在 Qwen3.5-4B 和 9B 上各训了一个版本，评测三个公开基准：OmniSpatial-PT（分 Ego / Allo / Hypo 三类视角）、3DSRBench（朝向与多物体关系）、ViewSpatial-Bench（以人为视角的物体朝向与相对方向）。

主要结果：LeRF-9B 在 Allo 与 Hypo 上分别比 backbone 提高 6.91 与 11.08 个百分点（54.04 对 47.13，55.66 对 44.58），在 ViewSpatial-Bench 的 P-Rel 上提高 8.72 个百分点（74.23 对 65.51），并在 OmniSpatial-PT Hypo、ViewSpatial P-Obj 上超过文中评测的所有闭源模型。

但同一张表里还有一行需要正视： Ego 从 80.20 掉到了 74.31。作者把它解释为一种取舍——模型把更多注意力放到“换视角”上，对本来就该用相机视角回答的问题反而变弱了。这个下降幅度不算小（约 6 个百分点），说明模型在三类视角上的表现存在取舍。

参考系本身估得准不准，作者单独做了评测。在 EMDB 与 OmniNOCS-Objectron 的采样子集上，LeRF-9B 的 All@15° 从 backbone 的 1.11% 提到 43.12%，超过专门估计朝向的 OrientAnything-V2（19.35%）；All@30° 也从 4.43% 提到 70.05%。原点的定位更稳，达到 99.82% 与 87.95%。有意思的是在物体数据集上它并没有全面超过专家模型：All@15° 几乎持平（49.58 对 50.42），All@30° 反而落后（72.54 对 83.23）。这些结果说明， 它学到了可用于视角采择的通用参考系。

模型是否真的在用渲染出来的轴，作者做了两个干预。其一是看调用率：LeRF-9B 在自我中心问题上只有 2.94% 调用工具，而在需要换视角的两类问题上都超过 84%，说明“要不要建系”确实学到了。其二是把渲染出的坐标系在评测时旋转 90°：整体准确率从 57.97% 掉到 54.05%，其中 Hypothetical 掉了 7.95 个百分点，而 Ego 几乎不受影响。这个对照很有说服力——如果模型只是在用内部朝向先验，旋转图上的箭头不应该有这么大影响。

SFT 与 RL 的分工也在表里：只做 SFT 的检查点整体只有 40.86%，比基座还低；但以它为起点做 RL，最终达到 57.97%，高于直接从基座做 RL 的 53.76%。作者的解释是， SFT 单独看是“退化”，但它提供了 RL 更容易利用的初始朝向知识。另一个观察是：即使训练和评测都不用渲染，SFT→RL 仍有 57.18%，只差 0.79 个百分点；这说明参考系监督在内部留下了可用的空间先验，渲染图更多是给 Hypothetical 这类“看不见观察者”的问题提供一个视觉锚点。

图来自原论文 Figure 5：自我中心问题直接回答；他人中心与假想视角先预测并渲染坐标系，再读图作答。

核心点和不足

值得关注

这篇的价值不在于“又提了一个空间推理数据集上的点”，而在于换了一种中间表示。之前的两条路，一条是把三维坐标塞进上下文，一条是用外部模型重建场景再变换；前者把误差压给感知，后者把复杂度压给工程。LeRF 选的是第三条： 把参考系做成画在图像上的二维符号，让模型用自己最擅长的能力——读图——来完成本来需要空间变换的那一步。

这个选择也解释了它为什么能省掉外部模型：渲染函数是确定性的、无参数的，整个系统在推理时只多了一次画图。而且“要不要画”由模型自己决定，避免了“所有问题都强行变换”的浪费。

仍然存在的问题

首先是精度换来的表达力损失。二维投影只保留方向，不保留距离和尺度，论文自己也承认需要精确三维距离、强遮挡关系或复杂几何变换的问题不在射程内。这与场景理解任务的实际需求是有落差的。

其次是 Ego 上的退化。80.20 到 74.31 不是噪声级别，它意味着模型在“该直接用相机视角”时变笨了。论文把它当作取舍陈述，但没有给出缓解办法，比如按问题类型路由，或者在 RL 奖励里对 Ego 样本加权。

第三，参考系预测依赖实体有可辨识的朝向。遮挡、外观歧义、本身没有正面的物体（球形、成组的家具）都会让坐标轴失准；训练时干脆剔除了没有明确朝向的类别，这等于把困难样本移出了训练分布。失败案例里还能看到另一类错误：实体定位错了，坐标系就整个挂到别的物体上，后面的推理再正确也没用。

第四，RL 的奖励设计比较粗。只看最终答案对错，意味着一个碰巧蒙对的答案和一个真读懂了的答案得到同样的信号；作者用“冻结参考系 token 的梯度”来防止坐标系被奖励带偏，但这也让两阶段之间失去联合优化的机会。

最后是范围：只处理静态单图。视频里实体在动、观察者在动，参考系需要跟踪和更新，误差还会随时间累积。作者把它列为未来工作，但这恰恰是机器人、具身交互最需要的场景。

总结

LeRF 的思路可以归纳成三步：

  • 让 VLM 判断当前问题是否需要换视角，不需要就直接答；
  • 需要时定位参考实体，预测它“前、左、上”三条轴在图像上的投影（原点 + 三个端点，整数坐标）；
  • 用确定性渲染器把轴画回原图，删掉数值参数，让模型读图上的方向作答。

训练上先 SFT 学“建系”，再用 GRPO 学“用系”，并把参考系预测的梯度隔开，避免强化学习把朝向能力带偏。

它提出的问题是 “视角变换这一步，是否必须发生在三维空间里”。LeRF 给出的回答是：可以发生在图上，前提是模型学会自己把参考系画出来。沿着这条线，下一步值得看的是两件事——如何在保留二维轻量表示的同时补回距离信息，以及如何把这个参考系扩展到会动的场景里。
