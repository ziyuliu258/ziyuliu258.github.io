Arch Linux KDE Wayland 下腾讯会议屏幕共享黑屏修复

发表于2026-07-23|更新于2026-07-29|技术
|总字数:2k|阅读时长:7分钟|浏览量:

问题现象

大概一两个月前，在 KDE Plasma Wayland 环境中使用腾讯会议时，突然无法正常查看其他参会者共享的屏幕了，这个情况困扰了我很久，导致经常不得不用手机来参会。今天有空闲时间，上网搜索了一下，终于找到了解决方案。

本机环境大致如下：

  • Arch Linux
  • KDE Plasma Wayland
  • wemeet-bin 3.26.10.401-1
  • Intel 核显 + NVIDIA RTX 4060 Max-Q 混合显卡
  • xdg-desktop-portal-kde、PipeWire、WirePlumber

原因定位

此前腾讯会议也有问题，根据AUR对应包的评论区中的建议，修改方案是添加一个环境变量：

这个主要是之前的解决方案，很长一段时间内是管用的。但是最近失灵了。根据Arch Linux CN论坛中网友的说法，是以下两个地方出现问题：

1. Wemeet 的 DBus 调用存在时序问题

屏幕共享请求应该依次完成：

但当前版本在 SelectSources 完成前就调用了 Start。某些 portal 后端会容忍这个竞态，另一些后端则会导致共享请求失败或没有视频数据。

2. PipeWire 颜色格式协商不兼容

Wemeet 原本硬编码了 BGRx 等颜色格式，而当前 portal 后端可能协商出 RGBx。格式协商失败时，界面可能已经显示“正在共享”，但实际没有可显示的视频帧，于是看到黑屏或白屏。

具体解释还是要看源仓库中的文档。

解决方法

使用该网友自行逆向后给出的补丁 wemeet-screenshare-patch 修复 Wemeet 的屏幕共享二进制。该补丁包含：

  • Hunk 0：修复 DBus SelectSources 与 Start 的异步调用顺序。
  • Hunk 1a/1b：修复 PipeWire 的颜色格式协商，并通过 hook 转换缓冲区颜色格式。

不要安装旧的 wemeet-wayland-screenshare-git

这个项目已经归档，而且它仍然使用 OpenCV 旧版 C API。当前 Arch 的 OpenCV 5 已经移除了：

因此安装它会在编译阶段失败。这和 Wemeet 本次黑屏问题是两个不同的问题；当前应直接修补 wemeet-bin 自带的屏幕共享模块。

Warning

wemeet-screenshare-patch 直接修改 /opt/wemeet 和 /usr/lib/wemeet 中的二进制文件。以后升级 wemeet-bin 后，补丁可能被覆盖，需要重新备份、dry-run 并应用补丁。不要将 __EGL_VENDOR_LIBRARY_FILENAMES 全局写入系统环境变量，只对腾讯会议设置即可。

更新：升级后腾讯会议无法启动（2026-07-28）

升级 wemeet-bin 后，腾讯会议可能会在点击图标后立刻退出，甚至不会生成新的应用日志。这次实际升级的是包发布版本，从 3.26.10.401-1 升级到 3.26.10.401-4；应用自身版本号没有变化。

原因

新版 Arch 包的 /usr/bin/wemeet 启动脚本在开头启用了 set -u，但随后直接展开了可能未定义的 $LD_LIBRARY_PATH：

KDE 图形会话通常没有预先定义 LD_LIBRARY_PATH，于是脚本会直接报错并退出：

这发生在腾讯会议进程真正启动之前，因此不是屏幕共享补丁本身导致的。

同时，包升级会用原版文件覆盖 /opt/wemeet/bin/modules/screen_share/libscreen_share_module.so，使二进制补丁失效；但之前创建的用户级桌面文件仍会加载 libhook.so。此时只剩 hook 而没有对应的二进制改动，属于不完整的残留补丁配置，不应继续使用。Mesa EGL 的选择则是另一个独立的渲染兼容性设置，不能和 hook 一起一概移除。

修复：恢复干净启动，并绕过包装脚本缺陷

不要修改 /usr/bin/wemeet，否则下次更新还会被覆盖。保留用户级桌面文件 ~/.local/share/applications/wemeetapp.desktop，但将它的 Exec 改成下面这一行：

这行配置先给 LD_LIBRARY_PATH 设定非空的安全值。包装脚本再追加同一路径后会得到 /usr/lib/wemeet:/usr/lib/wemeet，避免 set -u 因变量未定义而退出，也避免空路径段被动态链接器解释为当前工作目录。它移除了旧配置中的 LD_PRELOAD=…libhook.so，从而停用升级后已不完整的屏幕共享补丁；但保留 __EGL_VENDOR_LIBRARY_FILENAMES=…50_mesa.json，让 XWayland 下的腾讯会议使用 Mesa/Intel EGL 实现，而非在 NVIDIA EGL 配置中创建窗口 surface。使用 wemeet-x11 会额外显式设置 EGL_PLATFORM=x11 和 QT_QPA_PLATFORM=xcb，避免普通 wemeet 在 Wayland 会话中遗漏 EGL 平台选择。

黑屏时保留 Mesa EGL 配置

如果腾讯会议能够进入会议，但视频或他人共享的画面变成黑屏，检查 Saas/Logs/xcast_*.log。若反复出现下面的记录：

其中 0x3005 是 EGL_BAD_CONFIG，说明 NVIDIA EGL 与 XWayland 窗口 surface 的配置不匹配。此时应保留上面的 __EGL_VENDOR_LIBRARY_FILENAMES=/usr/share/glvnd/egl_vendor.d/50_mesa.json；不要恢复 LD_PRELOAD，因为升级后的二进制模块尚未重新打补丁。

然后从应用菜单重新打开腾讯会议。这个修复只改用户目录中的启动器，不影响包文件，并能在以后更新 wemeet-bin 后继续生效。

需要重新修复屏幕共享时

先确认腾讯会议本身可以正常启动和参会。若之后仍需要屏幕共享修复，必须先对升级后的 libscreen_share_module.so 重新执行备份和 dry-run；确认所有 Hunk 匹配后，再应用二进制补丁并重新启用 hook。不要只恢复旧的 LD_PRELOAD 配置，因为它不会自动恢复已被包升级覆盖的二进制补丁。
